## Windows 本机三端联调

隔离端口启动实际 Agent、Master 和 Web 开发代理，共 9 项检查通过：

1. 构建并启动 Windows Agent、Master 与任务辅助程序。
2. Web 代理访问实际 Master，登录和鉴权可用。
3. 通过原 TCP 连接下发加密 YAML，应用确认在 Master 持久化。
4. 组件状态经 UDP 入库和 ACK，Agent 待发队列排空。
5. 原生 FIM 检测在线文件修改，事件到达 Master。
6. Agent 停止期间修改文件，重启后使用原基线检测变化。
7. 真实 `-task-run` 保留 stdout、stderr 和退出码，上报开始/完成记录。
8. Master 离线时任务退出码 7 留在加密 spool；双方重启后补传，事件不重复入库。
9. 合成 sudo I/O 验证共享 generation、乱序分片、重复 ACK、双文件关联、鉴权下载及字节一致性。

该联调没有伪装成 Linux 组件运行。sudo I/O 使用明确的合成分片；auditd、Tetragon、nft、GRUB 的真实安装与内核能力尚未在目标 Linux 上验证。测试进程已停止。

前端另外使用隔离 Master 及浏览器验证：预设和 sudo grants 合并到 YAML；修改表单后阻止旧 YAML 下发；运行、禁用和错误状态；主机系统/BTF；安全事件筛选；warning 待处理状态；任务输出 UTF-8 解码和截断提示。截图位于 Web 的 `docs/security-*-preview.jpg`，均标有“UI 验收示例包”。

## 交付物和下一步验收

`dist/security-v0.7.0/` 包含 Agent / Master 的 Linux 双架构二进制、生产前端、三个完整源码 ZIP、配置示例、手册、协议及本记录。构建产物有 SHA256 清单。包内不包含运行数据库、实际配置密文、测试登录会话或依赖缓存。

按 **Master → Web → Agent** 升级，先备份现有 SQLite 数据和部署配置。数据库升级后不能直接用旧 Master 打开；回退应配套恢复备份。保留现有 TCP、UDP、HTTP、反向代理和主机身份设置。

下一步在目标测试 Linux 主机下发基础预设，验收实际安装、配置校验、reload、审计日志、失败 SSH、FIM、断线补传和可选 sudo 下载；再按环境启用 Tetragon 或 enforce 策略。详细步骤与边界见 [安全组件接入与配置手册](安全组件接入与配置手册.md)。
