# 文件内容追溯与通知收敛（Agent v0.7.5）

原生文件监控只覆盖 `security.native_fim.paths` 指定的文件或目录，不会自动扫描整台机器。为需要追溯的脚本目录配置监控，例如：

```yaml
security:
  enabled: true
  native_fim:
    enabled: true
    paths:
      - /usr/local/123
    poll_interval_seconds: 30
    capture_created_content: true
    report_changes: false
    max_diff_bytes: 8192
```

将这些字段合并进现有 YAML，保留原有巡检、命令采集、上报及其他安全组件配置。已有版本不认识 `capture_created_content`，应先将 Agent 升级到 0.7.5，再更新 Master 与 Web，最后按需下发包含新字段的配置。新 Agent 在字段缺省时默认开启，因此现有已启用原生文件监控的配置也能留存后续新建文本。旧版 Agent 的既有事件不会补出从未采集的内容。

## 内容留存

监控首次建立基线时，原本已存在的文件仍只作为基线，不会因为默认开启新功能而全部上传正文。之后新增的非敏感普通文本文件会保留创建时可采集的内容及后续采到的版本。删除事件携带最后已采集文本和文件 SHA-256，删除原文件后仍可在事件详情的“文件内容留存”查看。此功能记录文件版本，不代表该版本一定已被某个进程执行；执行行为仍查看命令和系统审计记录。

`capture_created_content: false` 关闭新增文本自动留存。`report_changes: true` 则允许同时留存监控前已存在文件的受限文本及其后续变化；明确的 false 不会被自动改为 true。敏感路径（账户口令、私钥等）不采正文；二进制或非 UTF-8 内容只留元数据。

`max_diff_bytes` 为每一侧文本上限，默认 8192，范围 256–16384；超过时保留可传输的 UTF-8 前缀并标注截断。JSON 编码超出单条事件预算时还会进一步缩减前缀。页面区分完整采集、空文件、截断、二进制、敏感、关闭和未捕获；不能把“未捕获”当作“空文件”。这不是完整文件备份服务。

## 事件和通知

底层 inotify 的写入、属性、关闭等活动只触发采集与核对，不再逐条上报 `file_activity`。同一路径短时间活动归并，正常编辑产生一条对应实际目标文件的新增或修改事件；真正删除另产生删除事件。不同文件或真实生命周期转换不会被统一吞掉。

Vim 的交换文件、典型编辑器备份等窄范围临时文件默认不生成事件；直接指定临时文件本身为监控根时仍可监控。旧临时基线清理不会再制造一次删除告警。普通隐藏文件和任意 `.tmp` 文件不会被一律忽略。

Master 沿用 `(机器, 事件 ID)` 与通知任务唯一键去重，断网重传同一事件不会再增加一条记录或任务。聊天通知只显示操作、路径和内容留存状态；完整文本位于已认证的事件详情。Generic Webhook 原有原始 `data` 仍保留完整事件字段。

## 快速创建后删除的边界

Linux 在关闭写入、移动文件等活动时尽早捕获可获得的版本，再进行事件归并。若在采集前文件已经被删除，inotify 只有路径和事件类型，无法从已消失路径恢复正文；此时保留观测到的变更并明确标记内容未捕获。监控启动前、监听中断、队列溢出或文件整个生命周期发生在未被观测的间隙内，也不能承诺恢复其内容。

验收时先确认组件运行正常、目录已纳入监控并建立基线。新建脚本、等待新增事件后执行，再删除，删除详情应仍能显示已采集版本。再用 Vim 编辑保存，确认没有交换文件通知。使用同一终端瞬间创建并删除的测试应检查未捕获标记，不能以界面空白作为成功依据。
