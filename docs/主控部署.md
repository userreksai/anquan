# 安全中心主控部署

系统由三个独立仓库组成：Agent `anquan`、后端 `anquan-server-master`、前端 `anquan-server-web`。本工作区保留最新 Agent，另两个仓库分别位于同名子目录。

## 端口总览

以下为当前源码与部署配置的默认值，实际运行值以启动参数、环境变量和容器映射为准。

| 服务 | 目标端口 / 协议 | 访问方向 | 用途 |
|---|---|---|---|
| Vue 安全中心 / Nginx | `10111/TCP`（HTTP） | 管理员浏览器 → 前端 | 页面入口；浏览器的 `/api/` 请求也走此端口 |
| Go HTTP API | `10110/TCP`（HTTP） | 前端 Nginx / 开发代理 → 主控 | 登录、机器、事件、Webhook 管理接口 |
| Agent 事件接收 | `55555/UDP` | Agent → 主控 | 心跳、巡检摘要、告警、SSH 登录记录 |
| Webhook 通知（可选） | URL 指定的 TCP 端口；HTTPS 默认 `443`，HTTP 默认 `80` | 主控 → Webhook 接收方 | 主控主动发送通知，无需新增主控入站端口 |

浏览器入口为 `http://主控IP:10111`。前端代理将 `/api/` 转发到主控 `10110`，浏览器无需直接访问后端端口。

当前 `anquan-server-master/compose.yaml` 发布了宿主机 `10111/TCP`、`10110/TCP`、`55555/UDP`，映射未限定宿主机 IP。后端默认监听地址为 `:10110` 和 `:55555`；这些默认值并非仅限本机回环地址。网络是否可达还取决于宿主机网络和防火墙。

Agent 无固定入站监听端口，使用系统分配的临时 UDP 源端口向主控发送数据。只需打通 Agent 到主控的目标 UDP 端口；无需在 Agent 机器上开放 `55555`。模板 `server: []` 表示不向主控发送数据。

### 端口配置位置

| 调整项 | 配置位置 | 需要同步的地方 |
|---|---|---|
| 前端 `10111` | `anquan-server-web/nginx.conf` 的 `listen`；开发模式为 `vite.config.ts` 的 `server.port`；预览命令在 `package.json` | Compose 的 web 端口映射、浏览器访问地址 |
| 后端 `10110` | 主控 `--http` 参数或 `ANQUAN_HTTP_ADDR`；systemd 默认值在 `deploy/anquan-master.service` | Nginx 的 `proxy_pass`、开发代理 `API_PROXY_TARGET`；Docker 部署同时检查 Compose 环境变量和映射 |
| Agent 接收 `55555` | 主控 `--udp` 参数或 `ANQUAN_UDP_ADDR`；systemd 默认值在 `deploy/anquan-master.service` | Compose 环境变量和 UDP 映射、Agent 私有 YAML 的 `server`；Agent 配置变更后重新构建部署 |

Docker 的宿主机端口与容器端口可以不同。若只改宿主机映射，容器内监听端口和 Nginx 的容器间代理地址保持原值；浏览器及 Agent 使用各自实际发布的宿主机端口。开发、预览和生产前端都配置为 `10111`，在同一地址同时运行时需避免端口冲突。

### 无需额外开放的端口

- SQLite 使用本地文件 `/data/anquan/anquan.db`，首次启动自动创建目录及表，无数据库网络端口。
- Agent 只写 `.prom` 指标文件，不提供 HTTP 指标服务；单独部署 node_exporter 时按其实际配置另行登记端口。
- SSH 登录检测读取本机日志，不通过 SSH 连接采集，因此不会为此新增 `22/TCP` 的要求。
- `demo/watched/app.conf` 中的 `8080` 只是被监控文件内容，不是项目监听端口；测试中的临时端口也不属于部署清单。

首次登录：`admin` / `admin1818.`，密码含末尾英文句点。

## Docker Compose

把前后端源码放在同级目录：

```text
security-center/
  anquan-server-master/
  anquan-server-web/
```

```sh
cd anquan-server-master
docker compose up -d --build
docker compose logs -f master
```

打开 `http://主控IP:10111`。前端 Nginx 将 `/api/` 转发到主控 `10110`，无需配置浏览器跨域。SQLite 绑定宿主机 `/data/anquan`，重建容器保留数据库。内网打通 Agent 到主控 `55555/UDP` 的网络即可，无需登记令牌或配置 UDP 认证、加密。单独重建 master 容器后运行 `docker compose restart web`，使 Nginx 重新解析主控容器地址。

忘记密码时执行（交互输入，不写进命令行历史）：

```sh
docker compose exec master /app/reset-admin-password.sh
```

容器和 systemd 两种部署方式选择其一，避免同时启动两个主控写同一个数据库。

## systemd / Nginx

构建后端，或使用提供的对应 CPU 架构二进制：

```sh
cd anquan-server-master
CGO_ENABLED=0 go build -trimpath -o dist/anquan-master-linux-amd64 ./cmd/anquan-master
sudo sh deploy/install.sh ./dist/anquan-master-linux-amd64
```

安装器创建 `anquan` 系统账号、数据目录、systemd 服务和密码重置命令。日志使用 `journalctl -u anquan-master -f` 查看。服务环境变量可放 `/etc/anquan-master.env`，修改后执行 `sudo systemctl restart anquan-master`。

前端用 Node.js 24、pnpm 11.19.0 构建：

```sh
cd ../anquan-server-web
npm install --global pnpm@11.19.0
pnpm install --frozen-lockfile
pnpm run build
```

将 `dist/` 安装到 Nginx 静态目录，使用仓库 `nginx.conf`，并把 `root` 修改为实际目录、`proxy_pass http://master:10110` 修改为 `proxy_pass http://127.0.0.1:10110`。该配置监听 `10111`。

在主控服务器直接重置密码：

```sh
sudo anquan-reset-password
```

脚本隐藏输入并二次确认，通过标准输入调用主控的 `reset-admin` 命令。新密码长度为 8–72 字节，SQLite 中仅保存 bcrypt 哈希；重置后旧会话失效，无需重启主控。手工部署可设置 `ANQUAN_BIN` 和 `ANQUAN_DATA_DIR` 后运行 `sh deploy/reset-admin-password.sh`。

## 配置 Agent

在 Agent 构建机的私有配置中设置：

```yaml
server:
  - 172.22.0.100:55555
agent_ip: 172.22.0.101
setup:
  logs: /var/log/时间anquan.log
  prom: /var/lib/node_exporter/textfile_collector/process_monitor.prom
  interval_seconds: 300
```

将示例 IP 换成实际主控地址和被监控机器地址。`agent_ip` 可省略，默认使用访问主控的本地出口 IP。多网卡或 NAT 环境建议显式填写每台机器唯一的 IP；SSH 来源 IP 单独保存，不作为机器主键。

Agent 使用构建时内置配置，改完需要重新构建并部署：

```sh
go run ./cmd/anqu-build -config ./config.yaml -output ./dist/anqu-linux-amd64 -goos linux -goarch amd64
```

使用 `-service` 或提供的 systemd 服务启动 Agent。启动后立即上报心跳，主控自动以 IP 登记机器，无需手工添加；随后独立于巡检每 30 秒发送心跳。超过 90 秒没有收到机器上报，页面显示红色“异常离线”；恢复上报后自动恢复在线。页面每 15 秒刷新当前查询结果，保留筛选条件和页码。旧版 Agent 仍使用巡检摘要判断在线，缺省 300 秒巡检时，离线阈值为 15 分钟。

文件变动及缺失会显示中文标题、规则/路径、前后 MD5，SSH 登录逐条显示登录时间、来源 IP、用户和终端。时间筛选按事件发生时间，页面输入和显示使用浏览器本地时区，数据库按 UTC 保存。

## Webhook

在“Webhook 通知”页面新增一个或多个 URL，可单独启停、编辑、删除。默认飞书文本格式，复用了现有标题监控项目的请求与业务返回码检查；也支持企业微信及通用 JSON。只对新入库的告警发送通用通知，内容包含机器 IP、主机名、时间、告警类型、目标、描述及变更前后值。

告警与待投递通知在同一 SQLite 事务落盘，后台投递失败后重试，进程重启仍保留。重复收到同一事件不会再次产生通知。页面的测试按钮会向对应 URL 发出明确标记的测试通知。数据库应妥善备份，其中包含 webhook URL。

UDP 仍为尽力投递，没有 ACK 或持久重传；主控停机、网络丢包可能导致历史记录不完整，Agent 本地报告和日志仍保留完整检测结果。webhook 重试保障的是已成功进入主控数据库的告警。详细格式见 [Agent / Master 协议](agent-master-protocol.md)。
