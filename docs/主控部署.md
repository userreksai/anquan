# 安全中心主控部署

系统由三个独立仓库组成：Agent `anquan`、后端 `anquan-server-master`、前端 `anquan-server-web`。本工作区保留最新 Agent，另两个仓库分别位于同名子目录。

## 端口总览

以下为当前源码与部署配置的默认值，实际运行值以启动参数、环境变量和容器映射为准。

| 服务 | 目标端口 / 协议 | 访问方向 | 用途 |
|---|---|---|---|
| Vue 安全中心 / Nginx | `10111/TCP`（HTTP） | 管理员浏览器 → 前端 | 页面入口；浏览器的 `/api/` 请求也走此端口 |
| Go HTTP API | `10110/TCP`（HTTP） | 前端 Nginx / 开发代理 → 主控 | 登录、机器、事件、Webhook 管理接口 |
| Agent 事件接收 | `55555/UDP` | Agent → 主控 | 心跳、巡检摘要、告警、SSH 登录记录 |
| Agent 配置与安装下载 | `55556/TCP` | Agent 主动连接主控；主控沿连接下发 | 配置推送、应用确认、保活；临时授权的安装下载使用独立连接 |
| 安装软件源出口 | `80/TCP`、`443/TCP` | 主控 → 白名单公网软件源 | 下载软件源索引、组件及依赖；无需新增主控入站端口 |
| Webhook 通知（可选） | URL 指定的 TCP 端口；HTTPS 默认 `443`，HTTP 默认 `80` | 主控 → Webhook 接收方 | 主控主动发送通知，无需新增主控入站端口 |

浏览器入口为 `http://主控IP:10111`。前端代理将 `/api/` 转发到主控 `10110`，浏览器无需直接访问后端端口。

原生主控默认监听 HTTP `:10110`、UDP `:55555` 和配置 TCP `:55556`；网络是否可达还取决于宿主机网络和防火墙。配置下发功能按原生服务部署。

Agent 无远程入站监听端口，使用系统分配的临时 UDP 源端口上报，并主动连接主控 TCP 55556；安装期间仅增加本机 `127.0.0.1:随机端口` 临时代理。只需打通 Agent 到主控的 UDP 55555 与 TCP 55556 及连接返回流量；无需在 Agent 机器上开放这两个入站端口，也无需新增 55557。模板 server: [] 仅关闭 UDP 数据上报，配置 TCP 连接独立保留。配置通道按 IP 识别机器，仅向可信 Agent 网络开放；安装下载另由当前配置连接的短期令牌和主控限时开关约束。

### 端口配置位置

| 调整项 | 配置位置 | 需要同步的地方 |
|---|---|---|
| 前端 `10111` | `anquan-server-web/nginx.conf` 的 `listen`；开发模式为 `vite.config.ts` 的 `server.port`；预览命令在 `package.json` | Compose 的 web 端口映射、浏览器访问地址 |
| 后端 `10110` | 主控 `--http` 参数或 `ANQUAN_HTTP_ADDR`；systemd 默认值在 `deploy/anquan-master.service` | Nginx 的 `proxy_pass`、开发代理 `API_PROXY_TARGET`；Docker 部署同时检查 Compose 环境变量和映射 |
| Agent 接收 `55555` | 主控 `--udp` 参数或 `ANQUAN_UDP_ADDR`；systemd 默认值在 `deploy/anquan-master.service` | Compose 环境变量和 UDP 映射、Agent 生效配置中的 UDP server 列表；地址变更后重新加密并重启 Agent |
| 配置连接 `55556` | 主控 `--tcp` 参数或 `ANQUAN_TCP_ADDR`；systemd 已配置 | Agent 通过 ANQUAN_MASTER 独立指定配置连接目标，默认访问 TCP 55556 |

Docker 的宿主机端口与容器端口可以不同。若只改宿主机映射，容器内监听端口和 Nginx 的容器间代理地址保持原值；浏览器及 Agent 使用各自实际发布的宿主机端口。开发、预览和生产前端都配置为 `10111`，在同一地址同时运行时需避免端口冲突。

### 无需额外开放的端口

- SQLite 使用本地文件 `/data/anquan/anquan.db`，首次启动自动创建目录及表，无数据库网络端口。
- Agent 只写 `.prom` 指标文件，不提供 HTTP 指标服务；单独部署 node_exporter 时按其实际配置另行登记端口。
- SSH 登录检测读取本机日志，不通过 SSH 连接采集，因此不会为此新增 `22/TCP` 的要求。
- `demo/watched/app.conf` 中的 `8080` 只是被监控文件内容，不是项目监听端口；测试中的临时端口也不属于部署清单。

首次登录：`admin` / `admin1818.`，密码含末尾英文句点。

## Docker Compose

把前后端源码放在同级目录：

```text
security-center/
  anquan-server-master/
  anquan-server-web/
```

```sh
cd anquan-server-master
docker compose up -d --build
docker compose logs -f master
```

打开 `http://主控IP:10111`。前端 Nginx 将 `/api/` 转发到主控 `10110`，无需配置浏览器跨域。SQLite 绑定宿主机 `/data/anquan`，重建容器保留数据库。内网打通 Agent 到主控 `55555/UDP` 与 `55556/TCP`，并检查 Compose 已发布这两个协议对应的端口，无需配置 UDP 认证、加密。单独重建 master 容器后运行 `docker compose restart web`，使 Nginx 重新解析主控容器地址。

忘记密码时执行（交互输入，不写进命令行历史）：

```sh
docker compose exec master /app/reset-admin-password.sh
```

容器和 systemd 两种部署方式选择其一，避免同时启动两个主控写同一个数据库。

## systemd / Nginx

构建后端，或使用提供的对应 CPU 架构二进制：

```sh
cd anquan-server-master
CGO_ENABLED=0 go build -trimpath -o dist/anquan-master-linux-amd64 ./cmd/anquan-master
sudo sh deploy/install.sh ./dist/anquan-master-linux-amd64
```

安装器创建 `anquan` 系统账号、数据目录、systemd 服务和密码重置命令。日志使用 `journalctl -u anquan-master -f` 查看。服务环境变量可放 `/etc/anquan-master.env`，修改后执行 `sudo systemctl restart anquan-master`。

前端用 Node.js 24、pnpm 11.19.0 构建：

```sh
cd ../anquan-server-web
npm install --global pnpm@11.19.0
pnpm install --frozen-lockfile
pnpm run build
```

将 `dist/` 安装到 Nginx 静态目录，使用仓库 `nginx.conf`，并把 `root` 修改为实际目录、`proxy_pass http://master:10110` 修改为 `proxy_pass http://127.0.0.1:10110`。该配置监听 `10111`。

在主控服务器直接重置密码：

```sh
sudo anquan-reset-password
```

脚本隐藏输入并二次确认，通过标准输入调用主控的 `reset-admin` 命令。新密码长度为 8–72 字节，SQLite 中仅保存 bcrypt 哈希；重置后旧会话失效，无需重启主控。手工部署可设置 `ANQUAN_BIN` 和 `ANQUAN_DATA_DIR` 后运行 `sh deploy/reset-admin-password.sh`。

## 配置 Agent

在 Agent 构建机的私有配置中设置：

```yaml
server:
  - 172.22.0.100:55555
setup:
  logs: /var/log/时间anquan.log
  prom: /var/lib/node_exporter/textfile_collector/process_monitor.prom
  interval_seconds: 300
```

将 server 列表换成实际 UDP 接收主控地址，支持裸 IP 默认 55555。机器 IP 通过配置主控握手自动识别，无需填写 agent_ip。

v0.6.2 可不部署 `config.age`，先指定 Master 并常驻等待页面下发：

```sh
./dist/anqu-linux-amd64 -service -master 172.22.0.100
# systemd 也可设置 Environment=ANQUAN_MASTER=172.22.0.100。
```

Agent 会自动登记机器，未下发前保持运行而不巡检；收到配置后启用采集。连接地址自动加密保存到程序旁 `agent.connection.age`，旧 `agent.connection.json` 成功迁移后删除；后续无参数可使用平台缓存或启动时同步，执行一次并上报 SSH 登录。v0.6.6 机器身份使用到配置主控路由所选的本机网卡 IP，Nginx 中转来源由主控单独记录。元数据 v3 将 local_ip 与兼容回退 observed_ip 分开，重启仅恢复仍属于本机的 local_ip；TCP 未选定时共用首个可用 UDP 路由地址，不做公网探测。升级后按真实 IP 出现新的机器记录；旧代理聚合记录保留，需按真实机器重新确认下发配置。也可保留本地 `config.age` 作为回退配置，首次构建同时生成该文件：

```sh
go run ./cmd/anqu-build -config ./config.yaml -output ./dist/anqu-linux-amd64 -goos linux -goarch amd64
```

使用 `-service` 或提供的 systemd 服务启动 Agent。启动后立即上报心跳，主控自动以 IP 登记机器，无需手工添加；随后独立于巡检每 30 秒发送心跳。超过 90 秒没有收到机器上报，页面显示红色“异常离线”；恢复上报后自动恢复在线。页面每 15 秒刷新当前查询结果，保留筛选条件和页码。旧版 Agent 仍使用巡检摘要判断在线，缺省 300 秒巡检时，离线阈值为 15 分钟。

配套更新 Master、Web、Agent 后，在“管理设置 → Age 配置加密”编辑配置并点击“下发配置”，选择机器确认。Agent 在当前扫描结束后自动切换；不必重启服务。Master 保存每台机器的最新密文，未连接时等待重连。Agent 缓存为程序旁 `config.master.age`，启动优先读取，主控暂时不可达仍保留；没有给本机分配配置则使用可选本地 `config.age`，没有本地文件时保持等待。服务账号须能写 Agent 所在目录。下发 YAML 的 server 会立即切换全部 UDP 上报目标；配置主控 ANQUAN_MASTER 和自动 IP 独立于 YAML。

主控检查监听与配置连接：

```sh
sudo ss -ltnp 'sport = :55556'
sudo ss -tnp 'sport = :55556'
```

文件变动及缺失会显示中文标题、规则/路径、前后 MD5，SSH 登录逐条显示登录时间、来源 IP、用户和终端。时间筛选按事件发生时间，页面输入和显示使用浏览器本地时区，数据库按 UTC 保存。

## Agent 安装下载

Agent 所需 auditd、sudo、nftables 及传递依赖仍由节点自己的 APT/DNF/YUM 解析，Tetragon 仍使用固定版本发布包和 SHA256 校验；网络请求统一经过 Master 的 55556/TCP。下载能力不提供公开文件目录，Master 也不会用自身发行版的包替代节点的软件源。

1. 升级前停止 Master 并备份整个数据目录，或制作一致性的 SQLite 备份，再更新 Master、Agent 和 Web。本版将 Master 数据库迁移到 schema 10，旧 Master 不能直接打开迁移后的库。原生部署按上文重建并替换程序，Agent 替换前执行 `sudo systemctl stop agent.service`，替换后执行 `sudo systemctl start agent.service`；Docker 部署重建 Master/Web，并确认 55556/TCP 映射。旧 Master 无下载协议时，新 Agent 不会退回直连软件源。
2. 在主控确认到软件源的 DNS、80/443 出站可用。以 Ubuntu 为例，主控执行 `curl -4 -I --connect-timeout 5 --max-time 15 https://archive.ubuntu.com/ubuntu/dists/noble-updates/InRelease`。若主控也无公网出口，需先恢复出口或另行提供离线依赖；本功能不建立完整缓存镜像。
3. 打开 **管理设置 → Agent 安装下载**，核对允许域名，选择 15、30 或 60 分钟窗口并开启。默认包含 Ubuntu、Ubuntu EC2、Debian、部分 RPM 发行版源及 GitHub 发布下载所需域名；自定义源、镜像列表实际选出的镜像及重定向目标需逐个补充完整域名。仅内置 `*.ec2.archive.ubuntu.com` 支持通配，其余条目填写完整域名，不带协议、端口或路径。只接受公网 80/443，私网仓库不能通过此出口转发。
4. 对目标机器下发启用了 `security.install_missing: true` 的组件配置。Agent 在实际下载时申请短期会话，临时代理只监听 `127.0.0.1`，不改全局 APT/YUM 配置。页面可查看到期时间、活动会话/连接、传输字节与最近错误。
5. 等待机器显示 **已应用** 并核对组件状态，然后立即关闭下载。关闭或窗口到期会撤销下载连接；Master 重启后默认关闭，窗口时长和允许域名保留。配置 TCP 55556 继续监听，配置接收和心跳不依赖下载开关。

总下载窗口只允许 Agent 在安装期间申请会话，不会主动替任何节点安装组件。单安装会话目前最长 10 分钟，且不超过总窗口到期时间；超时后可在允许窗口内重新下发重试。软件源配置、发行版/架构、索引有效性及 GPG 签名仍由节点包管理器校验；Tetragon 的 TLS 和 SHA256 校验保留。APT 配置若有按域名指定的代理或 `DIRECT` 覆盖项，Agent 会明确拒绝自动安装，需先由管理员核对移除冲突项。有 Master 的 Agent 不会在下载被拒绝、超时或断线后直接访问公网。关闭下载不影响已安装组件，也不会卸载失败安装过程中已装好的包。

首次安装 Tetragon 时，节点还必须已有 util-linux 提供的 `unshare`，并允许创建网络 namespace（可用 `sudo unshare --net -- true` 检查）。发布包下载并校验后，安装脚本在隔离网络中执行，避免脚本自行绕过 Master 下载。命令缺失、容器权限或主机策略禁止 namespace 时，安装明确失败，不能关闭隔离后回退直连；可由管理员先完成受控预装，再让 Agent 接管已有 Tetragon。已有 Tetragon 的正常配置和监控不要求重新安装。

在 `172.22.0.11` 这类无法出网的 Linux 节点验收时，保留到 `172.22.0.27:55556` 的连接，开启窗口后重新下发配置，并检查：

```sh
sudo journalctl -u agent.service -n 100 --no-pager -o short-iso
command -v auditctl
sudo systemctl status auditd --no-pager -l
```

应看到组件安装成功及 `configuration_applied`，页面由待应用变为已应用。关闭窗口后，选择仍缺少组件的测试节点重新下发，应明确显示下载已关闭的失败原因，且无 Agent 公网直连。超长安装错误会按回执长度限制截断并显示失败，完整包管理器输出留在 Agent 日志。Windows 单元测试和交叉编译不能替代这一步 Linux 真实 APT/DNF 安装验收。

回滚时先关闭下载并停止服务，恢复备份程序和前端构建；若恢复不支持 schema 10 的旧 Master，必须同时恢复升级前的一致性数据库备份，不能只替换主控程序或手工降低 `PRAGMA user_version`。恢复旧库会丢失备份后写入的事件和管理变更，回滚前另存当前数据。恢复旧 Agent 可能重新使用原有公网直连安装行为，需结合现有网络策略确认；也可预装依赖并设置 `security.install_missing: false`。无需新增或移除 55557 防火墙规则，不删除现有 Agent 配置缓存和组件状态目录。

## Webhook

在“Webhook 通知”页面新增一个或多个 URL，可单独启停、编辑、删除。默认飞书文本格式，复用了现有标题监控项目的请求与业务返回码检查；也支持企业微信及通用 JSON。只对新入库的告警发送通用通知，内容包含机器 IP、主机名、时间、告警类型、目标、描述及变更前后值。

告警与待投递通知在同一 SQLite 事务落盘，后台投递失败后重试，进程重启仍保留。重复收到同一事件不会再次产生通知。页面的测试按钮会向对应 URL 发出明确标记的测试通知。数据库应妥善备份，其中包含 webhook URL。

UDP 仍为尽力投递，没有 ACK 或持久重传；主控停机、网络丢包可能导致历史记录不完整，Agent 本地报告和日志仍保留完整检测结果。webhook 重试保障的是已成功进入主控数据库的告警。详细格式见 [Agent / Master 协议](agent-master-protocol.md)。
