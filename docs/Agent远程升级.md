# Agent 远程升级

从 v0.7.3 开始，主控支持读取本机编译产物、自动打包，并将程序更新下发给页面选中的 Agent。更新复用 TCP 55556，不需要开放 55557 或 Agent 入站端口。更新包只包含 `anquan` 程序，不覆盖 `config.age`、主控配置缓存、连接设置、日志和采集状态。

## 首次接入

0.7.2 及更早的 Agent 没有接收程序更新的逻辑，需要先按原有手工部署方式安装一次 0.7.3 或更高支持版，并启动 `agent.service`。旧 Agent 会在页面显示为不支持远程升级，不能仅通过更新主控就让其获得接收能力。

本功能用于固定安装在 `/usr/local/anquan/anquan`、以 root 运行的 Linux systemd 服务。节点需要 `systemctl` 和 `systemd-run`。一次性扫描进程不接受程序更新。

## 编译与发布

在主控的 Agent 源码目录执行原有编译命令：

```sh
cd /usr/local/anquan-agent
git pull --ff-only origin master
go run ./cmd/anqu-build \
  -output ./dist/anquan \
  -goos linux \
  -goarch "$(go env GOARCH)"
ls -l ./dist/anquan ./dist/anquan.update.json
```

新版构建工具自动生成 `anquan.update.json`，包含程序版本、操作系统、架构、SHA-256 和字节数。版本读取自实际编译源码中的版本声明，不运行交叉编译的程序。手动修改元数据中的版本不能代替发布新版本；Agent 安装前还会检查程序实际输出的 `-version`。

主控默认读取 `/usr/local/anquan-agent/dist`，可通过环境变量 `ANQUAN_AGENT_DIST_DIR` 指定其他目录。目录中需要匹配的 `anquan` 和 `anquan.update.json`。主控不会直接分发已有的 `anquan.tar.gz`，会重新核对文件并生成只包含程序的升级包，避免混入配置或其他源码。

在页面“管理设置 → Agent 程序更新”操作：

1. 点击“读取并打包”，核对版本、平台和包校验值。
2. 选择在线、支持升级且平台一致的机器。
3. 核对目标版本和机器清单，点击“开始升级”。Agent 服务会短暂重启。
4. 查看每台机器的下载、重启、成功、失败或已回滚状态。

只允许升级到更高的正式三段数字版本，例如 `0.7.3` 到 `0.7.4`。当前发布包只对应一个操作系统和架构；amd64 包不能下发给 arm64。离线机器不排队自动执行。新发布包更换后需要重新确认目标。

主控保存已打包的独立快照；后续重新编译 `dist/anquan` 不会改变已经下发的任务。程序更新与“Agent 安装下载”的软件源代理开关独立：显式选择机器后只授权下载该次本地程序包，不需要开启公网软件源下载窗口。

## 主控权限与容器部署

主控运行用户需要读取源目录的权限，以及写入自身数据目录的权限。构建工具默认将程序设为 0700；若主控使用其他用户运行，需要给主控用户或所属组授予读取权限。主控读取程序打包时不执行该程序。

原生默认安装的主控使用 `anquan` 账号。若在 root 下编译，可在每次编译后给主控组读取权限：

```sh
sudo chgrp anquan ./dist/anquan ./dist/anquan.update.json
sudo chmod 0750 ./dist/anquan
sudo chmod 0640 ./dist/anquan.update.json
sudo -u anquan test -r /usr/local/anquan-agent/dist/anquan
sudo -u anquan test -r /usr/local/anquan-agent/dist/anquan.update.json
```

还需保证该账号能够遍历源目录各级父目录。使用其他服务账号时，替换组名和测试账号。新编译会创建新文件，旧文件的组权限不会自动继承。

容器部署需要把主机的编译产物目录以只读方式挂载至容器内，并设置对应的 `ANQUAN_AGENT_DIST_DIR`。仅挂载目录不会自动解决宿主文件的 UID/GID 读取权限。请同时备份主控数据库和更新快照目录；数据库内包含发布与任务记录及更新签名密钥。

## 校验、重启和失败恢复

主控给每个升级任务签名，并发放绑定当前机器连接和短期任务的下载令牌。Agent 首次在配置好的主控连接上接收并固定主控更新公钥，后续拒绝公钥变化。因此首次接入应在受信任内网完成；该机制不为现有明文 TCP 链路补充 TLS。主控迁移时应保留签名密钥，不能把普通重启当作更换密钥的理由。

Agent 校验签名、有效期、版本、架构、压缩包及程序的大小和 SHA-256；解压只接受固定文件名的普通程序文件。升级辅助进程独立于 `agent.service`，使用同一安装目录中的暂存程序和旧版备份进行替换。新实例重新连接并确认任务、版本与程序校验值后，才会回报升级成功。超时或新程序无法启动时，辅助进程尝试恢复旧程序并启动旧服务；错误会保留在任务结果中。

普通下载和校验失败不会替换当前程序。不要在升级期间手工覆盖程序或并行操作服务。备份恢复只针对程序，不对其他版本可能产生的数据格式迁移作通用回滚保证。

升级辅助进程不能保证断电、系统崩溃或 systemd 整体故障后的自动恢复。若新程序已经替换且无法执行，启动检查也无法运行，需要管理员根据节点保留的升级记录和旧程序备份恢复，再检查 `journalctl -u agent.service` 与主控任务结果。请先在少量测试机器验证，再分批更新。
