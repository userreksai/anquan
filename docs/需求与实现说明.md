# 安全巡检程序：需求与实现说明（v0.3.0）

当前版本在 **A 构建机** 读取当前目录的 `config.yaml`，校验并加密内置到节点程序。**B/C 节点只部署程序，不需要 YAML、JSON 配置或独立文件清单。** 按需修改 A 的 YAML 并重新编译，即可生成适用于其他机器的程序。巡检报告仍输出 JSON 和 `.prom`，MD5 状态仍为 JSON，JSONL 登录日志继续支持。

## 一、需求整理

| 编号 | 用户需求 | 本版落实方式 |
|---|---|---|
| 1 | 对指定路径的文件做 MD5 校验；有变化时输出文件并汇总 | 按配置扫描文件/目录，持久化基线，比较并记录新增、修改、删除；每轮生成 JSON 汇总 |
| 2 | 输出 node-exporter 格式的文件，保存在 `/usr/local/anqu/`，以时间命名 | 生成 `时间.prom` 和 `时间.json`，文件名含纳秒与时区；同时更新 `textfile/anqu.prom` 用于采集 |
| 3 | 读取最近一次登录，包含来源 IP、时间、用户、分配终端 | 默认读取配置路径的 wtmp，调用 util-linux `last`；也支持包含四字段的 JSONL |
| 4 | 判断配置文件列表中的文件是否存在，并指定检查目录 | 在同一个 YAML 的 `existence.files` 中填写清单，`base_dir` 指定相对路径根目录；支持文件、目录和任意类型 |
| 5 | 使用 Go，配置集中在一个 YAML，取消 JSON 配置 | A 的构建工具读取 YAML，检查清单写入 `existence.files`，移除 `existence.list_file` |
| 6 | A 编译后直接部署 B/C，节点不显示配置 | AES-256-GCM 加密内置，节点不读取外部配置、不提供配置导出接口，默认执行不打印配置或摘要 |
| 7 | 修改 YAML 可用于其他机器 | A 修改后重新构建；支持选择 Linux amd64/arm64 等目标架构，无需改业务源码 |
| 8 | 便于排查 | 按用户确认，报告和指标继续显示真实监控路径；不宣称加密能防止 root、反编译或内存提取 |
| 9 | 整理功能并交付 | 提供源码、YAML 模板、测试、演示、systemd 单元和 Linux 构建工具包；真实节点程序由 A 根据配置生成 |

## 二、已实现功能

### 1. 文件 MD5

- 多个路径，路径可为文件或目录。
- 递归开关、指定路径排除，自动排除自身输出与状态文件。
- 初次建立基线；随后与上次成功扫描比较。
- 新增、修改、删除分类；记录文件路径、变化前后 MD5。
- 记录本轮数量、累计变化数量和最近发现变化时间。
- 文件读取失败或基线异常时保留原基线；避免误报删除。
- 目录消失后报告消失路径和原文件删除。
- Linux 文件锁、原子替换文件，减少并发执行和采集半写文件的问题。

### 2. 最近一次登录

- 默认数据源 `/var/log/wtmp`，路径可修改。
- 返回 `source_ip`、`login_time`、`user`、`terminal`。
- 支持 IPv4、IPv6，跳过重启等系统记录。
- 登录时间统一转换为配置时区。
- JSONL 自定义数据源按时间选择最新记录。
- 区分“数据源没有记录”和“读取/解析失败”。

### 3. 文件/目录存在检查

- 在 `existence.files` 中配置检查清单，通过 `existence.base_dir` 设置目标根目录。
- 相对路径拼接根目录，绝对路径直接使用。
- 判断是否存在、实际类型、类型是否符合。
- 缺失、类型不符、权限或访问错误分别记录。
- 使用 `os.Stat`：符号链接按目标判断，断链按缺失处理；MD5 模块则跳过符号链接。

### 4. 汇总与运行

- 每次运行输出按时间命名的 JSON 和 `.prom`，包括没有变化的批次。
- JSON 保存明细，`.prom` 提供指标；最新指标放在单独子目录。
- 对三个模块分别报告成功状态，部分失败不阻止其他模块输出。
- 支持单次执行和 systemd 定时执行，示例周期五分钟。
- 构建时读取并严格校验 YAML，支持中文注释；运行时仅使用内置配置。
- 节点程序仅提供 `-help`、`-version`，取消 `-config` 与 `-check-config`。
- 默认输出目录 `/usr/local/anqu/`，可以在配置中改动。

### 5. 配置内置与构建

- `go run ./cmd/anqu-build` 默认读取当前工作目录的 `config.yaml`，也可用 `-config` 指定 YAML。
- 每次构建随机生成 AES-256-GCM 密钥和 nonce，将加密配置通过 Go overlay 内置到程序。
- 构建临时目录不保存配置明文，独立临时 Go 编译缓存结束后清理；A 的原始 YAML 保留。
- 去除 Go 调试符号、构建路径和构建 ID，减小直接检索的信息暴露。
- 目标系统默认 Linux，架构可指定；目标节点不需要安装 Go，wtmp 模式需要兼容的 `last`。
- 节点不提供配置查看命令，但独立程序含有解密所需信息，因此无法保证配置无法恢复。

## 三、第一版采用的需求解释

| 项目 | 本版约定 |
|---|---|
| “有变更” | 文件内容与上次成功扫描不同，或文件新增/删除；首次建立基线不算变化 |
| “最近一次登录” | 当前配置的数据源中最新的成功登录记录，不是每个用户各一条 |
| “登录日志路径” | 可以配置 wtmp 或约定的 JSONL 文件；不猜测任意文本日志格式 |
| “判断哪个目录” | `md5.paths` 指定 MD5 监控路径；`existence.base_dir` 指定检查清单的相对路径根目录 |
| “文件以时间命名” | 历史 `.json`、`.prom` 文件都以时间命名；固定文件名的最新指标另放 `textfile/` |
| 汇总时机 | 每轮输出一个报告，变化明细置于 `md5.changes`；累计计数也保存在基线中 |
| 变更是否告警 | 生成文件、指标及退出码；通知渠道不在第一版内 |
| 基线更新方式 | 每次成功扫描自动更新，不等待人工确认 |
| 配置相对路径 | 在 B/C 上以程序所在目录为基准；`state_file` 相对于输出目录，清单项相对于 `existence.base_dir` |
| 配置修改生效 | 在 A 修改、重新构建，下发并替换 B/C 程序后生效 |
| 配置保护范围 | 减少明文配置分发和直接暴露；不承诺抵抗本机管理员、反编译或内存提取 |

## 四、附件参考及未实现范围

附件 `anquan.sh.txt` 是 SSH 登录通知脚本，其中的注释、白名单、通知地址仅作参考，未作为本程序的运行指令或默认配置。附件记录的日志缺少终端字段，白名单登录也不会形成完整记录，因此本版通过 wtmp 或完整 JSONL 获得四个字段。

以下功能不属于当前第一版：飞书通知、IP 地理位置、IP 白名单过滤、安装 SSH 登录钩子、实时文件事件监听、任意 `auth.log`/`secure` 文本解析、多文件轮转合并、固定可信基线审批、历史报告自动清理、独立 HTTP exporter 服务、Web 页面。程序通过 node_exporter 现有服务提供指标。

MD5 只用于此次要求的内容变化核对；本版不声称能抵抗有本机修改权限的攻击者同时修改文件和基线，也不是防篡改证据系统。

## 五、部署时填写的信息

1. 实际 Linux 发行版、CPU 架构，是否安装兼容的 util-linux `last`，是否写入 wtmp。
2. 需要做 MD5 的文件/目录、是否递归、排除项。
3. `existence.files` 清单中的路径及预期类型、相对路径根目录。
4. 登录数据源种类和日志路径。
5. 输出目录、时区、执行周期，以及历史报告保留策略。
6. node_exporter 启动参数和读取指标目录的权限。

前五项中的路径、模块设置和时区在 A 的 YAML 中填写并内置；定时周期和 node_exporter 参数在节点部署时配置。A 无需存在 B/C 被监控的文件。一个构建可供路径相同且架构兼容的多个节点使用。

### 读取与输出位置速查

| 位置 | 所在机器及用途 |
|---|---|
| 当前目录 `config.yaml` | A：唯一配置输入，仅在构建时读取，可用构建工具 `-config` 改路径 |
| `/usr/local/anqu/anqu` | B/C：内置配置的节点程序，直接执行 |
| `/usr/local/anqu/时间.json` | B/C：完整巡检报告，含真实路径与前后 MD5 |
| `/usr/local/anqu/时间.prom` | B/C：本轮 Prometheus 文本指标归档 |
| `/usr/local/anqu/textfile/anqu.prom` | B/C：最新指标，node_exporter 只采集此子目录 |
| `/usr/local/anqu/state/md5.json` | B/C：MD5 基线及累计计数，程序自动维护 |
| `/var/log/wtmp` 或配置的 JSONL | B/C：登录数据源，属于采集数据，不是程序配置 |

上述节点输出路径为默认值。报告、指标和基线没有加密，会透露监控范围；这是保留真实路径用于排查的明确选择。

## 六、建议验收步骤

1. 用演示 YAML 构建后运行程序：生成初始基线，MD5 变化数为 0，看到模拟登录和存在检查结果。
2. 修改、新增和删除监控文件：分别得到 `modified`、`added`、`deleted`，JSON 含前后 MD5。
3. 不再改动后继续运行：本轮变化数为 0，累计变化数保留。
4. 删除检查清单中的一个文件，或把预期文件改为目录：报告缺失或类型不符。
5. 在测试主机登录一次：核对 IP、登录时间、用户、终端与 `last` 的实际输出一致。
6. 在 A 把登录路径改成不存在的路径并重新构建：节点报告采集失败，其他模块仍输出。
7. node_exporter 指向 `/usr/local/anqu/textfile`：检查 `/metrics` 中的 `anqu_` 指标和 `node_textfile_scrape_error`。
8. 安装 timer：检查五分钟周期运行、退出码、指标更新时间及报告生成。
9. 仅拷贝节点程序到新的安装目录，不放配置文件：绝对路径正常使用，相对路径按程序所在目录解析。
10. 修改 A 的 YAML，不替换节点程序时设置不变；重新构建并替换后生效。
11. JSON 配置、旧 `list_file` 和节点 `-config` / `-check-config` 入口均被拒绝。

测试和构建结果记录在发布包 `BUILD-INFO.txt`；目标主机验收尚未执行。

## 七、已有服务器升级到内置配置

先在 A 的源码目录拉取新代码，准备私有配置：

```sh
git pull --ff-only origin master

# 旧节点已经用 YAML 时，可将实际配置复制到 A 的源码根目录
# 下面的 root@B 要替换为真实登录地址；A 已有配置时不要覆盖
scp root@B:/usr/local/anqu/config.yaml ./config.yaml
chmod 0600 config.yaml
vi config.yaml
```

旧版本仍用 JSON 时，在 A 复制 `configs/config.example.yaml` 为 `config.yaml`，把旧主配置的实际值迁入；将旧 `files.json` 条目写入 `existence.files`，删除 `existence.list_file`。不要把 JSON 直接改扩展名。保留实际监控路径、排除/递归规则和输出/状态位置可继续使用旧基线；旧相对路径应确认在新程序安装目录下仍解析到同一位置，或改为绝对路径。

在 A 校验并构建，原节点任务可继续运行：

```sh
go test ./...
go vet ./...
go run ./cmd/anqu-build -config ./config.yaml -output ./dist/anqu-linux-amd64 -goos linux -goarch amd64

# 只下发程序和部署单元，不下发配置
scp ./dist/anqu-linux-amd64 deploy/anqu.service deploy/anqu.timer root@B:/tmp/
```

在 B 节点更新（ARM64 请相应更换程序文件名）：

```sh
sudo systemctl stop anqu.timer
sudo systemctl stop anqu.service
sudo install -m 0700 /tmp/anqu-linux-amd64 /usr/local/anqu/anqu
sudo install -m 0644 /tmp/anqu.service /etc/systemd/system/anqu.service
sudo install -m 0644 /tmp/anqu.timer /etc/systemd/system/anqu.timer
sudo systemctl daemon-reload
sudo systemctl start anqu.service
sudo systemctl start anqu.timer
sudo journalctl -u anqu.service -n 30 --no-pager
sudo ls -lt /usr/local/anqu/
```

若自定义过 systemd 单元，应保留所需设置，将 `ExecStart` 改为单独的 `/usr/local/anqu/anqu`。附带服务接受退出码 `2`（发现变化/缺失/类型不符），并设置 `LimitCORE=0` 以减少意外 dump。

**确认 A 已保存实际配置、新程序运行正常后，移走或删除 B/C 遗留的明文配置和旧源码副本。** 升级程序不会自动删除用户文件。标准安装路径下的旧配置可这样清理；不要删除报告或 `state/md5.json`：

```sh
sudo rm -f -- /usr/local/anqu/config.yaml /usr/local/anqu/config.yml \
  /usr/local/anqu/config.json /usr/local/anqu/files.json
```

以前在 `/usr/local/anquan` 等目录拉取过源码的，还需自行检查其中是否留有真实配置及备份。不要仅把旧配置改名留在节点；删除文件也不能保证它已从磁盘快照、备份或已被读取的副本中消失。

以后在 A 修改 YAML、重新构建，再替换节点程序。保持监控范围不变时保留旧 MD5 基线；修改 MD5 扫描范围需要按 README 备份并重建基线。新配置文件仅保存在 A，节点不需要也不会读取它。
