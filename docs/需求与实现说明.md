# 安全巡检程序：需求与实现说明（v0.2.0）

当前版本将主配置与文件存在检查清单合并为一个带中文注释的 `/usr/local/anqu/config.yaml`。巡检报告仍输出 JSON 和 `.prom`，MD5 状态文件仍为 JSON。

## 一、需求整理

| 编号 | 用户需求 | 本版落实方式 |
|---|---|---|
| 1 | 对指定路径的文件做 MD5 校验；有变化时输出文件并汇总 | 按配置扫描文件/目录，持久化基线，比较并记录新增、修改、删除；每轮生成 JSON 汇总 |
| 2 | 输出 node-exporter 格式的文件，保存在 `/usr/local/anqu/`，以时间命名 | 生成 `时间.prom` 和 `时间.json`，文件名含纳秒与时区；同时更新 `textfile/anqu.prom` 用于采集 |
| 3 | 读取最近一次登录，包含来源 IP、时间、用户、分配终端 | 默认读取配置路径的 wtmp，调用 util-linux `last`；也支持包含四字段的 JSONL |
| 4 | 判断配置文件列表中的文件是否存在，并指定检查目录 | 在同一个 YAML 的 `existence.files` 中填写清单，`base_dir` 指定相对路径根目录；支持文件、目录和任意类型 |
| 5 | 使用 Go，保留读取配置文件的方式 | 通过 `-config` 加载 YAML，路径、模块开关、时区均可配置；兼容显式指定旧 JSON |
| 6 | 先交付第一版，并整理需求和已实现功能 | 提供源码、示例配置、测试、演示数据、systemd 单元、Linux 可执行文件及使用文档 |

## 二、已实现功能

### 1. 文件 MD5

- 多个路径，路径可为文件或目录。
- 递归开关、指定路径排除，自动排除自身输出与状态文件。
- 初次建立基线；随后与上次成功扫描比较。
- 新增、修改、删除分类；记录文件路径、变化前后 MD5。
- 记录本轮数量、累计变化数量和最近发现变化时间。
- 文件读取失败或基线异常时保留原基线；避免误报删除。
- 目录消失后报告消失路径和原文件删除。
- Linux 文件锁、原子替换文件，减少并发执行和采集半写文件的问题。

### 2. 最近一次登录

- 默认数据源 `/var/log/wtmp`，路径可修改。
- 返回 `source_ip`、`login_time`、`user`、`terminal`。
- 支持 IPv4、IPv6，跳过重启等系统记录。
- 登录时间统一转换为配置时区。
- JSONL 自定义数据源按时间选择最新记录。
- 区分“数据源没有记录”和“读取/解析失败”。

### 3. 文件/目录存在检查

- 在 `existence.files` 中配置检查清单，通过 `existence.base_dir` 设置目标根目录。
- 相对路径拼接根目录，绝对路径直接使用。
- 判断是否存在、实际类型、类型是否符合。
- 缺失、类型不符、权限或访问错误分别记录。
- 使用 `os.Stat`：符号链接按目标判断，断链按缺失处理；MD5 模块则跳过符号链接。

### 4. 汇总与运行

- 每次运行输出按时间命名的 JSON 和 `.prom`，包括没有变化的批次。
- JSON 保存明细，`.prom` 提供指标；最新指标放在单独子目录。
- 对三个模块分别报告成功状态，部分失败不阻止其他模块输出。
- 支持单次执行和 systemd 定时执行，示例周期五分钟。
- 每次重新读取同一个 YAML 配置及其中的清单；支持中文注释并提供配置预检查命令。
- 默认输出目录 `/usr/local/anqu/`，可以在配置中改动。

## 三、第一版采用的需求解释

| 项目 | 本版约定 |
|---|---|
| “有变更” | 文件内容与上次成功扫描不同，或文件新增/删除；首次建立基线不算变化 |
| “最近一次登录” | 当前配置的数据源中最新的成功登录记录，不是每个用户各一条 |
| “登录日志路径” | 可以配置 wtmp 或约定的 JSONL 文件；不猜测任意文本日志格式 |
| “判断哪个目录” | `md5.paths` 指定 MD5 监控路径；`existence.base_dir` 指定检查清单的相对路径根目录 |
| “文件以时间命名” | 历史 `.json`、`.prom` 文件都以时间命名；固定文件名的最新指标另放 `textfile/` |
| 汇总时机 | 每轮输出一个报告，变化明细置于 `md5.changes`；累计计数也保存在基线中 |
| 变更是否告警 | 生成文件、指标及退出码；通知渠道不在第一版内 |
| 基线更新方式 | 每次成功扫描自动更新，不等待人工确认 |

## 四、附件参考及未实现范围

附件 `anquan.sh.txt` 是 SSH 登录通知脚本，其中的注释、白名单、通知地址仅作参考，未作为本程序的运行指令或默认配置。附件记录的日志缺少终端字段，白名单登录也不会形成完整记录，因此本版通过 wtmp 或完整 JSONL 获得四个字段。

以下功能不属于当前第一版：飞书通知、IP 地理位置、IP 白名单过滤、安装 SSH 登录钩子、实时文件事件监听、任意 `auth.log`/`secure` 文本解析、多文件轮转合并、固定可信基线审批、历史报告自动清理、独立 HTTP exporter 服务、Web 页面。程序通过 node_exporter 现有服务提供指标。

MD5 只用于此次要求的内容变化核对；本版不声称能抵抗有本机修改权限的攻击者同时修改文件和基线，也不是防篡改证据系统。

## 五、部署时填写的信息

1. 实际 Linux 发行版、CPU 架构，是否安装兼容的 util-linux `last`，是否写入 wtmp。
2. 需要做 MD5 的文件/目录、是否递归、排除项。
3. `existence.files` 清单中的路径及预期类型、相对路径根目录。
4. 登录数据源种类和日志路径。
5. 输出目录、时区、执行周期，以及历史报告保留策略。
6. node_exporter 启动参数和读取指标目录的权限。

这些都通过配置或部署单元提供，程序无需硬编码目标主机的信息。

## 六、建议验收步骤

1. 用演示配置运行：生成初始基线，MD5 变化数为 0，看到模拟登录和存在检查结果。
2. 修改、新增和删除监控文件：分别得到 `modified`、`added`、`deleted`，JSON 含前后 MD5。
3. 不再改动后继续运行：本轮变化数为 0，累计变化数保留。
4. 删除检查清单中的一个文件，或把预期文件改为目录：报告缺失或类型不符。
5. 在测试主机登录一次：核对 IP、登录时间、用户、终端与 `last` 的实际输出一致。
6. 把登录路径改成不存在的路径：采集失败应明确报错，其他模块仍输出。
7. node_exporter 指向 `/usr/local/anqu/textfile`：检查 `/metrics` 中的 `anqu_` 指标和 `node_textfile_scrape_error`。
8. 安装 timer：检查五分钟周期运行、退出码、指标更新时间及报告生成。

测试和构建结果记录在发布包 `BUILD-INFO.txt`；目标主机验收尚未执行。

## 七、已有服务器升级为单 YAML 配置

在源码目录中拉取并编译：

```sh
git pull --ff-only origin master
go test ./...
CGO_ENABLED=0 go build -trimpath -o anqu ./cmd/anqu
```

先准备配置。如果 `config.yaml` 已经存在，不要覆盖它：

```sh
if [ ! -e /usr/local/anqu/config.yaml ]; then
  sudo install -m 0640 configs/config.example.yaml /usr/local/anqu/config.yaml
fi
sudo vi /usr/local/anqu/config.yaml
```

将旧 `config.json` 的实际监控路径、排除项、递归设置、输出/状态位置、时区与登录设置搬入 YAML；将旧 `files.json` 的所有条目搬入 `existence.files`。模板内路径只是示例，不要直接覆盖自己已有的监控范围。保持这些 MD5 设置不变，即可复用旧基线。

```sh
# 先用刚编译的新版程序校验新配置，原任务可以继续运行
sudo ./anqu -config /usr/local/anqu/config.yaml -check-config

# 校验通过后，停止旧任务并更新程序、服务配置
sudo systemctl stop anqu.timer
sudo systemctl stop anqu.service
sudo install -m 0755 ./anqu /usr/local/anqu/anqu
sudo install -m 0644 deploy/anqu.service /etc/systemd/system/anqu.service
sudo systemctl daemon-reload
sudo systemctl start anqu.service
sudo systemctl start anqu.timer
sudo journalctl -u anqu.service -n 30 --no-pager
```

后续只编辑 `/usr/local/anqu/config.yaml`。旧 JSON 配置可以保留作备份；默认启动路径已改为 YAML。若自定义过 systemd 单元，保留原有其他设置，仅将 `ExecStart` 的配置路径改为 `/usr/local/anqu/config.yaml`。
