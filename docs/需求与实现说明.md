# 安全检测 Agent：需求与实现说明（v0.6.9）

本文记录 anquan Agent 的检测行为；主控和前端分别由 anquan-server-master、anquan-server-web 提供。Agent 使用兼容 v1 的 UDP 数据报接口上报。完整配置和部署命令见 [README](../README.md) 与 [配置模板](../configs/config.example.yaml)，主控对接字段见 [协议文档](agent-master-protocol.md)。

## 需求与实现

| 需求 | 实现与验收依据 |
|---|---|
| 服务启动记录当前时间 | `-service` 启动写入 `service_started`，单次启动写入 `agent_started`；包含北京时间、主机名、PID 和版本 |
| 每次完整巡检记录当前机器检测结果 | `-scan` 或常驻巡检写 `scan_started`、完整模块结果、逐条告警和 `scan_complete`；按所选登录模式处理登录，正常结果也保留 |
| 无 MD5 初始化，之后按变更后的结果比较 | `FilesMonitoring.fils/dir/search` 未提供 MD5 时建立持久化基线；之后比较上次成功扫描并在详细日志和指标成功后提交下一基线 |
| 多路径、多已知 MD5 | 同条规则 `路径1|路径2,MD5a,MD5b,MD5c`；每个文件各自命中任一已知值即正常，已知值不用全部使用 |
| 未知 MD5 独立建基线 | fils、dir、search 初始化时记录每个未知文件的 MD5；之后未知内容变化产生 `modified`，命中已知值则放行；规则明细区分 matched、baseline_tracked 和缺失数量 |
| 缺失文件通知 | 每轮产生 `missing`；首次缺失不妨碍其他正常文件建立基线，后来出现时产生 `added` |
| 目录文件增加、删除、内容变化 | 递归处理普通文件，记录 `added/deleted/modified`、路径和前后 MD5；固定 MD5 规则仍检查目录成员增删 |
| 按文件名从多个根目录搜索 | `文件名,目录1|目录2[,MD5...]` 递归精确匹配文件名，检查每个匹配文件；无结果产生 `not_found` |
| 进程适配多个系统 | `ProcessMonitoring.exists` 每行 `命令1|命令2|...`，任意一个完整命令行匹配即正常 |
| 进程列表及白名单 | `Process: {}` 开启首次列表初始化和滚动比较；以完整命令和实例数量检测增删；白名单只抑制列表变化告警，不免除 exists 检查 |
| 每次执行立即上报真实 SSH 登录 | 默认 `login.mode: trigger`，已安装路径无参或 `-ssh-report` 每次经 root 服务请求真实认证记录，生成独立执行 ID；保留原 `login_time`、`source_record_id`，附带 `trigger: execution`、`invoked_at`、`executed_by`；不消费 `.logins` 或修改 Prom |
| 持续增量采集 SSH 登录 | 显式 `login.mode: poll` 保留 v0.6.7 行为：按 `login.poll_interval_ms` 默认每 1000 毫秒读取 journal 的 sshd/sshd-session 成功认证，沿用持久化游标；此模式不接受执行上报请求 |
| SSH 登录通知 | 登录上报不等待默认 300 秒完整巡检；trigger 的每次独立执行分别入库、向已启用 webhook 入队，重复报文按事件 ID 去重；poll 保留来源记录去重，通知失败持久重试；最终耗时取决于网络、主控与机器人接收端 |
| 实时读取操作命令 | `history` 首次分批补传 history.log，之后按加密字节游标增量读取；独立于巡检，每秒检查追加内容，上传时间、用户、终端、完整单行命令 |
| 北京时间零点切日志 | `setup.logs` 中的 时间/{date} 生成 `YYYYMMDD` 文件；每次写入按 UTC+08:00 日期选择日志，与宿主机时区无关 |
| 每轮更新固定 .prom | `setup.prom` 默认写入 `process_monitor.prom`，每轮原子覆盖，不添加时间前缀；默认间隔 300 秒 |
| UDP 对接主控 | 配置 `server: [域名或IP:port]` 后发送 heartbeat、scan_summary、alert 和独立采集的 ssh_login 数据报；裸主机名默认 UDP 55555；机器 IP 从连接到配置主控的本机路由自动识别，Nginx 中转地址单独记录；空列表保持本地记录 |
| 按机器下发配置 | 页面选择机器，Master 持久保存 age 配置，通过 Agent 主动连接的 TCP 55556 长连接推送；Agent 校验、原子缓存并在扫描间切换后确认；本地 config.age 可选，无配置时常驻等待下发；执行请求使用服务当前有效配置，完整单次巡检使用 `-scan` |
| 任意目录启动自动安装 | Linux 无参执行上传文件创建 `/usr/local/anquan/`，state/logs/textfile 按需创建，安装自身为 `anquan`，创建并启用启动 `agent.service`，固定连接 `172.22.0.27:55556/TCP`；首次需 root 和 systemd，help/version 不安装；已有目标配置不被覆盖；已安装路径无参改为一次 SSH 执行上报 |
| 自动安装 SSH 登录入口 | 原两行 `/usr/local/ssh-init.sh` 与 `/etc/ssh/sshrc` 软链保持兼容，静默执行 `/usr/local/anquan/anquan`；ubuntu 等普通用户经内核身份验证的 Unix IPC 请求 root 服务读取配置/日志，无须读取 0600 文件；入口不重复启停 systemd |
| 上传文件与安装目录同名 | `/usr/local/anquan` 为当前运行的普通程序文件时，先临时保留到同父目录唯一备份，再创建安装目录，无参安装和服务启动成功后清除本次备份，失败保留供重试；仅 root 可执行此搬迁；其它文件或符号链接保持原样并返回错误 |
| 取消时间戳 JSON 和服务锁文件 | 不再生成每轮时间戳 `.json`，保留日志、指标和加密状态；Linux 标准安装的常驻锁和 SSH socket 收敛至 `/run/anquan/`，保持独立权限和稳定锁 inode，不生成 `config.master.age.service.lock`；自定义路径行为兼容，历史文件不自动删除 |
| 连接信息加密 | 保存为 `agent.connection.age`，旧 `agent.connection.json` 成功加密迁移后删除；Master IP 保留动态配置，内置配套 age 密钥只能隐藏明文，无法防 root 或逆向提取 |

## 配置与构建方式

Agent 构建时内置配套解密身份，节点读取可执行文件旁的 `config.age`，不读取明文 YAML。修改配置后重新加密并替换 `config.age`，重启 Agent 生效，无需重新编译。新格式保留用户约定的 `fils` 拼写及大小写，未知字段和非法哈希会在配置解析时被拒绝。`md51` 等仅是需求描述里的占位值，实际配置必须填写 32 位十六进制 MD5。

文件监控中 `|` 表示每个路径都要检查；进程 exists 中 `|` 表示任意一个备选满足即可。两者语义不同。不存在文件、未知 MD5 后续变化和必须进程缺失都属于检测告警，区别于采集权限不足或状态文件损坏等执行错误。

首次已知不存在的根路径会告警，同时对其余成功读取的文件建基线。权限不足、文件读取中变化、目录遍历错误等不完整扫描则保留旧基线，不能当成删除。固定 MD5 允许值始终由配置决定，不会被当前内容覆盖。符号链接不跟随；已跟踪对象被替换为链接或特殊文件时显式报错。

旧 md5、existence 配置保持兼容。文件、进程和登录状态分别加密保存在 `state_file.files`、`state_file.processes`、`state_file.logins`，旧 `state_file` 基线也加密。每次启动按当前配置重新建立文件/进程基线；poll 沿用同一 `.logins`，不需要删除状态或重放已读登录，trigger 不读取或推进增量游标。状态格式及升级步骤详见 README。

## 日志与输出

日志是每行一个 JSON 对象：统一外层字段为 time、host、event、data。模块结果保留每个受检文件的实际哈希和状态、规则统计、完整进程清单，以及本轮全部新增登录。告警同时单独输出为 `alert` 事件，成功登录输出为 `ssh_login` 事件。基线更新前先写入详细日志和指标；崩溃可能重复记录，但不会故意消费尚未写出的变更。

trigger 执行写 `ssh_login` 与 `ssh_execution_complete`，后者含执行 ID、原认证 ID、调用者身份和 UDP 发送结果。poll 有新增登录时写 `ssh_poll_complete` 与逐条 `ssh_login`，空闲不逐秒写日志，错误写 `ssh_login_error` 并节流。排查登录时按 mode 查看对应日志，不仅查看 300 秒完整巡检的 `scan_complete` 或摘要中的登录数量。

每轮原子覆盖 `setup.prom` 和 `output_dir/textfile/anqu.prom`，不再生成时间戳命名的完整 JSON 报告。`setup.prom` 默认文件名为 `process_monitor.prom`，兼容旧配置时移除文件名中的 时间/{date}/{time}；其指标继续使用 `anqu_snapshot_` 前缀和 host/run_id 标签，最新状态指标继续使用稳定的 `anqu_` 前缀，指标包含采集完成时间。已有历史报告和指标文件不会自动删除。

`-scan` 退出码：0 为完成且无告警，2 为完成且发现告警，1 为配置、采集、输出、状态保存或 UDP 发送错误。无参执行上报与 `-ssh-report` 成功为 0、失败为 1。常驻服务启动后立即完整巡检，之后按 `setup.interval_seconds` 节拍运行，默认 300 秒；不并发扫描，慢于周期时跳过过期节拍。trigger 服务巡检不自动补发登录；poll 另用 `login.poll_interval_ms` 独立采集。独立心跳与 history 保留。单轮错误保留在日志中，并继续下一轮；收到停止信号后完成当前扫描再退出。

## SSH 登录覆盖范围

v0.6.8 省略 `login.mode` 时使用 trigger，旧两行 sshrc 入口每次执行请求上报一次。root 服务按可信调用者和 SSH 连接匹配真实认证；非 root 必须处于可验证的 SSH 上下文，不能自行指定其他用户。root 没有 `SSH_CONNECTION` 时允许最近真实认证快照；没有真实记录则报错，不编造时间。仅本地服务 socket 不可用时，root 可以使用有效缓存直接上报，不进行 TCP 配置同步；服务明确拒绝时不走回退。

显式 `login.mode: poll` 才启用每秒独立增量采集和原有游标去重，且拒绝执行上报请求。`login.poll_interval_ms` 允许 100–60000 毫秒，省略时默认 1000；`setup.interval_seconds` 继续控制完整文件/进程巡检。每秒是采集节奏，不能保证系统日志写入、Master 入库和机器人网络投递都在一秒内完成。以下持久化续读描述适用于 poll：

- journal 是默认生产方式：首次默认回看 24 小时；之后按持久化游标续读。max_records 限制每轮处理的事件数，积压留给后续轮次，不只取最新一条。
- authlog 支持 auth.log/secure 成功认证行、字节偏移和保留的未压缩轮转文件。初次只读当前文件；轮转历史缺失、已压缩或截断到无法恢复时显式报错。
- jsonl 用于自定义日志和演示，支持同一时间多个事件、分页及重启去重。
- wtmp 兼容保留，但只覆盖系统实际写入的登录会话，不能保证非交互 SSH 都有记录；因此逐次 SSH 监控应使用 journal 或完整 authlog。

认证行没有终端时写 `N/A`，不虚构分配终端。已被操作系统清理的登录历史无法恢复。Linux 目标节点需要读取系统日志和 /proc 的权限。

## 通知接口

UDP 消息字段为 version、event_id、ip、host、time、type、data。完整巡检向每个配置地址发送 scan_summary（含 interval_seconds）和逐条 alert；trigger 执行请求或 poll 新登录发送逐条 ssh_login。v0.6.6 起的 ip 使用到配置主控的 TCP 路由所选本机地址；TCP 未取得身份时共用首个可用 UDP 路由地址。Nginx 中转来源由主控另存；旧 Agent 保持主控回传来源地址的识别流程。仍无身份时由 UDP 接收端按来源登记。ssh_login 保留真实登录时间；trigger 每次执行使用新 ID，相同原认证的独立执行分别入库通知，重传同一执行仍去重；poll 继续按来源 ID 去重。常规巡检、登录及心跳仍采用尽力发送，没有主控确认或持久重传；本地日志仍保存完整证据。

v0.6.0 操作命令使用独立 `command_history` 通道和可选 `ack_requested` 字段。待发批次及下一读取位置原子加密保存为 `.commands`，Master 落库确认后清空；断线与重启继续重传，主控幂等入库。所有配置的 Master 均确认后继续下一批。命令游标不受每次启动文件/进程重建基线影响，源 history.log 不被修改、清空或轮转。正常命令不触发 webhook，Web 新增“操作命令”分类及每 2 秒刷新。

Agent 接受 Master 下发的 age 配置，配置优先级为有效主控配置、可执行目录下的可选本地 `config.age`。新机自动服务固定连接 `172.22.0.27`；前台/单次模式保留 `-master` / `ANQUAN_MASTER` 和保存地址优先级，无本地配置和保存地址时使用固定 IP 兜底。无配置时常驻等待下发而不采集；自动保存的连接信息支持此后无参数执行一次并上报 SSH 登录。TCP 55556 由 Master 监听，Agent 主动连接、断线重连，配置切换不需要在 Agent 上开放端口。下发可修改 UDP server 列表（支持域名），不能修改启动时的配置 TCP 地址及自动识别身份，也没有远程命令执行功能。server: [] 仅关闭 UDP 上报，配置 TCP 连接不受影响。配置缓存、确认和传输边界见 [协议文档](agent-master-protocol.md)。

## 部署与验证

`deploy/anqu.service` 是 -service 常驻服务；`deploy/anqu-oneshot.service` 与 `deploy/anqu.timer` 是可选外部调度方案，二者择一启用。从旧版本迁移时先停旧 timer，保留配置与状态备份后替换程序和单元。

自动验证覆盖文件生命周期、多对多允许值、递归搜索、缺失与读取错误、进程 OR 和白名单、实例数变化、每条登录和重启续读、日志跨北京时间午夜、UDP 本地数据报、固定指标文件覆盖和旧时间模板兼容、发布失败不推进状态，以及常驻调度出错后继续运行。旧版配置与内置加密构建测试继续执行。

Windows 上的模拟测试、加密 agent 冒烟运行以及 Linux amd64/arm64 交叉构建均已通过。此工作区没有可用的 Linux 运行环境，真实 /proc、journal、systemd、node_exporter 抓取和实际主控接收端仍需目标机验收。当前周期采样不能检测两轮之间发生又恢复的短暂文件或进程变化。
