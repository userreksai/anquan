# 安全组件接入与配置手册

本版采用“Agent 原生能力＋成熟系统组件”的分工。管理员在前端配置和选择机器；Agent 自动初始化组件、生成专用配置、验证并重载；Master 接收状态、安全事件和可选 sudo 录制文件。无需先手写 auditd、sudo 或 Tetragon 配置。

## 1. 保持不变的架构

| 项目 | 本版行为 |
|---|---|
| Agent 安装入口 | 原来的 root 无参数执行、自动安装 `agent.service` |
| 安装位置 | `/usr/local/anquan/anquan` |
| 默认配置主控 | 仍为 `172.22.0.27`，TCP 默认 `55556` |
| 数据上报 | 仍由 YAML `server` 指定，UDP 默认 `55555` |
| Master HTTP / Web | 沿用原部署、反向代理、登录和端口配置 |
| 配置下发 | 原加密 YAML、配置修订号、机器选择、TCP 长连接、应用确认 |
| 组件安装下载 | 复用 Master TCP 55556 的独立下载连接，管理限时开启，不新增 55557 |
| 身份 | 原本机路由 IP 识别；不新增另一套主机 ID |
| 数据存储与告警 | 原 Master SQLite、事件查询、webhook 队列 |

Tetragon 如启用，仅使用本机 Unix socket，不额外开放远程采集端口。sudo 文件也通过原 UDP 上报和 ACK 链路分片传输。

## 2. 本版使用的组件

| 组件 | 默认预设 | 功能 | 安装来源 |
|---|---|---|---|
| Agent 原生 FIM | 开启 | SHA256、文件增删、权限/属主、链接目标；Linux 实时通知＋周期核对；加密基线跨重启保留 | Agent 二进制内置 |
| Linux Audit / auditd | 开启 | 有登录身份的外部命令执行、指定文件写入/属性变更；关联审计多条记录及身份信息 | 节点 apt-get / dnf / yum |
| sudo | 开启日志和 I/O 录制 | sudo 事件、录制会话索引、可选完整录制文件上传；可选受控授权片段 | 优先复用现有 sudo，缺失时系统包管理器安装 |
| Tetragon | 可选，默认关闭 | 进程执行/退出和可选 TracingPolicy 事件 | 固定版本 v1.7.1；官方 HTTPS 发布包并校验 SHA256 |
| nftables | 仅启用来源限制且 enforce 时需要 | 按实际 SSH 监听端口限制新连接来源；IPv4/IPv6；保留已建立连接 | 复用现有 nft，必要时系统包管理器安装 |
| sshd、sysctl、systemd、GRUB | 复用系统能力 | SSH、内核参数、会话超时、Ctrl+Alt+Del、GRUB 认证策略 | 不替换系统实现 |
| Agent SSH 失败采集 | 默认预设开启 | journal 增量采集失败认证，按 IP 时间窗口识别重复失败 | Agent 内置，依赖 Linux journalctl |
| Agent 任务包装器 | 内置 | 显式包装的任务开始、结束、退出码、耗时及有限输出 | 同一个 Agent 二进制 |

没有引入 Wazuh Agent/Manager、rsyslog 转发链或 intimesec。当前目标中的 FIM 由 Agent 承担，身份归因借助 auditd，上传复用现有 Master。安装组件不代表获得它的所有产品能力；Tetragon 未配置额外策略时主要提供基础进程事件。

auditd、sudo、nft 的版本由节点发行版软件源提供，实际版本会随组件状态上报。本版不会自动升级已安装的 Tetragon；调整 `version` 影响缺失组件的首次安装，不等于执行已有组件升级。

Tetragon 版本优先通过配套 `tetra` 查询本机 Unix socket 上正在运行的服务端，只采纳 `Server version:`，不把 CLI 版本或命令错误当作守护进程版本。CLI 缺失或查询失败时，从已安装的 `tetragon` 二进制 Go 构建信息读取实际版本；不使用配置中的目标安装版本推测。失败或空结果不缓存，下次状态上报会重试；成功结果在当前 Agent 进程内缓存。此探测修复需要更新并重启 Agent，主控和前端沿用现有版本字段展示，历史状态记录保留原值。

组件仍按 `status_interval_seconds` 检查健康状态（默认 30 秒），首次及检查发现有意义的状态变化时上报完整状态；稳定不变时默认每 5 分钟刷新一次最新快照，较长或不能整除的检查周期按实际检查次数计算刷新间隔并随快照上报。队列计数及采样时间变化不会单独触发上报，原生文件监控、SSH 失败采集和任务包装器的健康变化同样参与判断。配套新版 Master 对正常状态仅更新最新快照，异常首次、异常内容变化及恢复正常才保留一次组件历史；新版 Web 按实际快照间隔判断过期。需配套更新 Master/Web，历史记录不批量删除。

仅命中内建 `anquan_exec` 规则的日常外部程序执行保持 `info` 级别，执行失败（例如 Shell 尝试不存在的命令路径）本身不再触发安全警告，原始审计成功/失败字段仍保留。自定义审计规则、混合自定义 key 或缺少内建 key 证据时不做这项降级。本机原始审计日志不受影响。主控“事件降噪与巡检保留”中的最低安全运行事件级别默认 `warning`，过滤普通执行与 sudo 信息记录；选择较低级别可恢复更多审计记录。SSH 登录通知、独立安全告警、操作命令及明确开启的 sudo 录制文件上传保持原处理方式。

## 3. 前端使用步骤

1. 先更新 Master 和 Web，再更新 Agent。旧 Master 不识别新增事件类型，不能作为本版数据接收端。
2. 新节点继续按原方式以 root 启动 Agent，登记到原主控并等待配置；已有节点替换二进制前先停止旧服务。
3. 登录前端进入 **组件与主机策略**。页面提供组件配置、实际状态和 sudo 会话文件列表。
4. 选择基础预设。默认安装 auditd、启用 sudo 录制和原生文件监控，Tetragon 关闭，主机策略为 `audit`。
5. 点击 **写入下方 YAML**。系统安全合并 `security` 段，保留原巡检、上报地址和其他配置；不会用字符串截断 YAML。之后沿用原机器选择和下发按钮。
6. 查看下发记录和组件状态。安装、配置校验或 reload 失败会显示错误，不能仅用“TCP 在线”判断组件已就绪。
7. 确实要修改主机策略时，启用具体策略并将 `policies.mode` 改为 `enforce`，再下发。SSH 用户、密钥、来源网段和启动密码均与具体环境有关，预设不会猜测并强制修改。

首次安装缺失组件前，先在 **管理设置 → Agent 安装下载** 核对允许软件源域名，选择 15/30/60 分钟并开启下载窗口，再执行第 5 步下发。Master 默认禁止下载，重启后也关闭；安装成功后可立即关闭，窗口到期也会自动关闭并终止活动下载。该开关仅授权安装期下载，55556 的配置监听、保活和已有组件继续工作。

可参考 [完整配置示例](../configs/security.example.yaml)。已有完整配置时，优先在原 YAML 上使用表单合并 `security` 段，保留原来的 `history`、巡检、登录及 `server`。整份替换为示例会关闭未包含在其中的可选模块；示例地址和路径也必须与节点实际设置核对。

**“操作命令”需要单独开启 `history`。** 它读取配置的 `history.path`（默认 `/var/log/history.log`），产生独立的 `command_history` 记录，不依赖 Tetragon，也不受安全运行事件级别和 Tetragon 类型屏蔽影响。当前标准 Linux 安装 `/usr/local/anquan/anquan` 明确启用后，会按 Agent 标准创建或统一命令脚本，普通用户经本地 Agent 服务提交命令；默认及自定义日志路径均支持。旧版 Agent 或自定义部署目录仍需已有记录机制。示例已包含该模块；不需要记录命令时设为 `history.enabled: false`，Agent 不会自动开启。

标准部署中，已有自定义或旧受管 `/etc/profile.d/history-audit.sh` 与当前标准不一致时，先备份再原子替换；原自定义逻辑需从备份另行迁移。日志只追加，属主和权限统一为 root:root 0644，日志内容和加密游标保留。已知旧脚本先备份修复 `200>` 并准备恢复凭证，再转换为当前受管脚本；只有已知截断损坏可在凭证核验后归档旧命令状态续采，单独替换脚本不重置游标。受管脚本在交互 Bash 中接管其他 DEBUG trap，保留可用提示符命令并规范可修改的 `PROMPT_COMMAND` 属性；只读等限制会使脚本加载返回非零并输出错误，需修正启动配置后重新登录。它不覆盖所有 Shell、非交互任务或任意系统调用。

首次创建记录 `history_script_installed`，替换记录 `history_script_replaced` 并带备份路径。创建、权限或命令服务预检失败会明确拒绝初始化；需通过 `history_command_ready` 和新会话探测命令验收。新钩子需退出 SSH 后重新登录，此前未生成或丢失的命令无法找回。

恢复原有命令采集时，将 `history` 加在 YAML 顶层，与 `login`、`security` 同级，不填入“Tetragon 配置”输入框；沿用原来的日志路径和 `history.timezone`，不要删除 `.commands` 状态来重置采集。未设置过独立时区时默认为 `Local`，必须与源日志时间含义一致。源日志已经追加但页面没有新增时，再检查 Agent 的 `history_error`、UDP 入库确认和页面筛选条件。详情见 [操作命令采集说明](YAML配置说明与示例.md#8-操作命令采集)。

**两个开关的含义不同：** `install_missing` 决定是否安装缺少的组件；`policies.mode: audit` 决定是否仅检查主机策略。audit 模式仍会安装、配置所启用的日志采集组件，但不应用 SSH、sysctl、sudo grants、超时、GRUB 等主机策略。

主控下载窗口是独立的第三项权限：即使 `install_missing: true`，没有下载授权也不能获取缺失组件。已预装依赖时不需要开启下载；可设置 `install_missing: false`，继续由 Agent 配置和监控现有组件。

## 4. 初始化、更新和失败处理

第一次有效配置到达前，Agent 维持原等待配置行为，不盲目安装组件。收到有效配置后执行组件初始化。缓存配置启动时，初始化在 worker 中进行，配置连接和心跳仍可运行。

热更新流程为：严格解析 YAML → 停止旧采集 worker → 检查组件/安装缺失包 → 生成受管配置 → 校验 → reload 或 restart → 保存加密配置缓存 → 启动新 worker → 回复原下发应用确认。过程失败会恢复受管配置和相应运行设置；包安装是追加动作，失败回滚不会卸载已经装好的包。

组件状态与配置下发状态分别展示。缓存配置在启动时初始化失败，会保留初始化错误，Agent 继续连接主控，管理员可以修正后重新下发；不能把服务仍在运行解读为新组件配置成功。

有 Master 的 Agent 安装期间仅启动 `127.0.0.1:随机端口` 临时代理，APT/DNF/YUM 的索引、包及依赖和 Tetragon 下载统一经过当前 Master 的 55556/TCP；安装结束关闭代理，不修改全局软件源或代理配置。节点继续负责本发行版/架构的依赖解析与签名验证，Tetragon 的 TLS、SHA256 校验保留。主控拒绝下载、断线或超时后不会回退到 Agent 公网直连；错误通过原配置 ACK 显示为失败，超长文本截断，完整日志留在节点。

主控必须能访问允许域名的公网 80/443，节点软件源也必须仍然有效；镜像选择、重定向或自定义源所需的额外域名需在管理页补充。转发限制只支持公网来源，不支持私网软件仓库。本功能提供统一网络出口，不保存完整离线包镜像；主控也无法出网时，应先恢复出口或另行预装离线依赖。关闭、会话过期或控制连接断开都会取消下载，修复原因后重新开启窗口并下发。升级和真实 Linux 安装验收见 [主控部署](主控部署.md#agent-安装下载)。

首次通过 Master 安装 Tetragon，还要求节点已具备 util-linux 的 `unshare`，且主机权限允许 `unshare --net` 创建网络 namespace。下载后的上游安装脚本在无网络的 namespace 执行，避免自行直连公网；命令缺失或 namespace 被禁止时明确失败，不会关闭隔离后重试。可由管理员受控预装后再下发配置；已有 Tetragon 会直接复用，不需要为本次下载功能重装。

auditd 启动时可能已把专用规则文件加载到内核。Agent 按完整规则逐条加载，只将单条规则的明确 `Rule exists` 视为已存在并继续加载后续规则；权限、语法、不可变审计配置等错误仍会导致应用失败并回滚。撤销和回滚按记录的完整规则处理，不使用 `auditctl -D` 或按 key 批量删除，因此不会因相同或相似 key 扩大删除范围。

运行规则的所有权与配置文件所有权分别记录：本轮实际新增成功的规则由 Agent 管理，原本已在内核中的规则仅复用。停用时只撤销 Agent 已记录拥有的运行规则；auditd 启动预加载、丢失清单或其他工具预先加载的规则可能继续保留。旧清单只有 key 时，仅当原专用文件确实由 Agent 拥有且内容哈希仍一致，才从该文件恢复完整规则信息；不根据 key 猜测所有权。

关闭组件、切回 audit 或移除策略时，会撤回本模块创建的专用配置；sysctl 和 Ctrl+Alt+Del 恢复首次管理前记录的值/状态，失败会明确报告。一次应用失败时，sysctl 恢复该次事务开始前的实际运行值，避免把较早的目标值误当作回滚前状态。不会卸载包、删除其他产品的规则，或清空整张主机防火墙。原有外部相同配置仅被引用时继续保留，因此撤回不等于重置整台主机为系统默认值。

同名专用文件已存在但没有 Agent 所有权记录时，普通文件的内容、权限与当前下发配置完全一致即可原样复用，并在加密清单中标记为“引用”，不会自动获得该文件的覆盖或删除权限；后续禁用组件仍保留这些文件。引用文件需要每次重新核对，内容或权限不同、文件类型不同、路径包含符号链接都会报告冲突。引用文件已被外部移除时，Agent 可以按下发配置新建文件，此时新文件才由 Agent 管理。引用文件保留意味着其中的外部配置仍可能被系统服务读取；组件禁用不代表这部分外部配置被卸载。

若出现 `already exists without agent ownership`，先确认 Agent 安装目录 `state/security/security-managed.state` 是否还在，及是否曾移动安装目录或清理状态。已验证一致的旧配置会由新版 Agent 复用；不一致时，应优先恢复原安装的加密清单，或先备份并迁移报错的冲突文件，再重新下发。错误按路径排序逐项指出，修复一个文件后仍可能发现其他组件的冲突；不要批量删除 `/etc/anquan` 或正在使用的状态目录。

`-scan` 仍是一次原有巡检，不负责组件初始化。它不会把新的组件配置仅缓存后就确认成“组件已生效”；新组件配置由 `-service` 常驻模式应用。

## 5. 生成的文件和生效方式

| 文件/位置 | 管理内容 | 应用方式 |
|---|---|---|
| `/etc/audit/rules.d/60-anquan.rules` | `anquan_exec` / `anquan_file` 及自定义 `anquan_*` 规则 | 逐条复用或加载；按完整规则撤回已记录拥有的旧规则；不按 key 批量清空 audit |
| `/etc/sudoers.d/90-anquan` | sudo 事件/I/O 日志和可选 grants | `visudo -cf`、`visudo -c` 验证，sudo 后续调用读取 |
| `/etc/sudoers.d/zzzz-anquan-restrict` | 显式 grants 的终端认证标签，及指定账户的拒绝规则 | 校验本地策略源、解析顺序、认证豁免、允许和拒绝探针 |
| `/etc/anquan/tetragon.conf.d/` | Agent 管理的 Tetragon 参数 | 专用 systemd drop-in 指向该目录并重启 |
| `/etc/systemd/system/tetragon.service.d/90-anquan.conf` | Tetragon 启动参数 | daemon-reload＋restart |
| `/etc/tetragon/tetragon.tp.d/anquan.yaml` | 可选 TracingPolicy | 重启 Tetragon 后加载 |
| `/etc/ssh/sshd_config.d/00-anquan.conf` | typed SSH 策略 | `sshd -t`、核对 `sshd -T`、reload |
| `/etc/anquan/ssh-allow.nft` | 专用 `inet anquan_ssh` 来源限制表 | `nft -c` 后原子应用 |
| `/etc/systemd/system/anquan-ssh-allow.service` | 重启后的来源限制恢复 | 专用 oneshot unit |
| `/etc/sysctl.d/90-anquan.conf` | 配置中的内核参数 | 保存原值，仅应用所选参数 |
| `/etc/profile.d/90-anquan-session.sh` | 交互 Bash 提示符超时 | 后续加载 profile 的会话 |
| `/etc/systemd/system.conf.d/90-anquan-ctrl-alt-del.conf` | 禁用连续 Ctrl+Alt+Del 的强制重启 | manager daemon-reexec，回读 CtrlAltDelBurstAction；同时 mask target |
| `/etc/grub.d/01_anquan` | 可选 GRUB 用户认证 | 支持 `update-grub` 的系统生成启动配置 |
| `/etc/default/grub.d/zzzz-anquan-single-user.cfg` | 生成带认证的恢复入口 | 解析实际 `/boot/grub/grub.cfg` 并运行 grub-script-check |
| `/var/log/anquan-sudo.log` | sudo 事件日志 | 由 Agent 增量采集 |
| `/var/log/anquan-sudo-io/` | sudo 原始录制文件 | 会话索引；可选稳定文件分片上传 |
| `/var/log/tetragon/tetragon.log` | Tetragon JSON 事件 | 增量读取，识别未压缩轮转文件 |

auditd 的源日志从 `/etc/audit/auditd.conf` 的 `log_file` 读取，未配置时使用 `/var/log/audit/audit.log`。不要求用户先改其主配置。

安装目录 `state/security/` 内按需保存加密的组件所有权、事务恢复数据、日志游标、FIM 基线、SSH 失败游标、任务 spool 和待发队列。它们绑定安装目录，调整普通 `output_dir` / `state_file` 不会重置这套组件状态。不要删除正在运行中的状态和锁文件。

## 6. 主要配置含义

| 字段 | 默认值/说明 |
|---|---|
| `security.enabled` | 旧配置省略即不开启新模块；基础预设为 true |
| `install_missing` | 基础预设为 true；网络受限时可预装后设 false |
| `poll_interval_seconds` | 2 秒，auditd/Tetragon/sudo 日志采集，范围 1–300 |
| `status_interval_seconds` | 健康检查默认 30 秒，范围 10–86400；状态变化上报，稳定时每 5 分钟更新快照 |
| `max_queue_events` | 10000，范围 100–100000；另有 256 MiB 总磁盘边界 |
| `auditd.audit_exec` | 默认预设开启，记录 `auid!=unset` 的 execve/execveat；不等于所有进程或用户输入 |
| `auditd.watch_paths` | 绝对路径数组；标准 cron 候选路径缺失时等待出现，其余显式路径缺失仍拒绝应用；权限或其他读取错误不会当作不存在忽略 |
| `auditd.rules` | 可选规则数组；只接受带 `anquan_*` key 的加法规则，拒绝清空/关闭全局 audit 的参数 |
| `native_fim.poll_interval_seconds` | 30 秒补扫；Linux inotify 另行触发及时核对 |
| `native_fim.capture_created_content` | 默认 true；保留监控基线建立后新建文本及其后续版本，删除时带最后采集内容；可显式 false 关闭 |
| `native_fim.report_changes` | 默认 false；开启后也留存监控前已有文件的受限前后文本，敏感路径不提供正文 |
| `native_fim.max_diff_bytes` | 默认 8192，范围 256–16384 |
| `ssh_auth` | 默认预设 5 秒读 journal；首次回看 300 秒；同 IP 300 秒内 5 次失败产生 warning |
| `sudo.io_logging` | 记录 sudo 管理的输入输出，不覆盖所有普通 Shell 会话 |
| `sudo.upload_io` | 默认 false；开启才上传原始录制文件，关闭时仍有本地录制和索引 |
| `sudo.max_session_bytes` | 默认 20 MiB，允许 1–200 MiB；另有单文件 64 MiB 上限 |
| `sudo.grants` | 默认空；user、run_as、commands、nopasswd；只有 enforce 写入，数组替换可移除本模块授权 |
| `sudo.restrict_users` | 默认空；最多 128 个唯一非 UID 0 本地账户；enforce 时先拒绝全部 sudo，再按 grants 精确放行 |
| `tetragon.version` | 空值按 v1.7.1 处理；默认预设已填写 |
| `tetragon.download_url` / `sha256` | 官方源可自动取校验值；自定义 HTTPS 地址需要明确 SHA256 |
| `tetragon.config` | 可选高级 daemon YAML；Agent 管理的导出路径、监听、轮转等参数不可覆盖 |
| `tetragon.tracing_policy` | 可选高级 TracingPolicy YAML；留空使用基础进程事件 |
| `policies.mode` | audit / enforce；默认 audit |
| `policies.ssh.allow_users` | 指定实际存在的账户，不默认写 ubuntu/ec2-user |
| `policies.ssh.allow_sources` | IP / CIDR 数组；IPv4、IPv6；不再使用 hosts.allow/deny |
| `policies.ssh.disable_forwarding` | 默认 false；启用后关闭 TCP、Unix socket、agent、X11 转发及隧道 |
| `policies.ssh.strong_crypto` | 默认 false；启用主机支持的强算法交集，校验实际生效值；旧客户端可能不兼容 |
| `policies.sysctl` | 字符串键值映射；默认空，不统一强制 rp_filter |
| `session_timeout_seconds` | 默认 0，不启用；60–86400 秒交互 Bash 提示符超时 |
| `disable_ctrl_alt_del` | 默认 false；启用时持久 mask target，且设置并核验 CtrlAltDelBurstAction=none |
| `policies.grub` | 默认关闭；强制模式需要 `grub-mkpasswd-pbkdf2` 产生的哈希，禁止明文口令 |
| `policies.grub.protect_single_user` | 默认 false；需启用 GRUB 认证，要求实际恢复/单用户/救援入口认证 |

未指定 `restrict_users` 时，grants 仅增加/移除 Agent 自己的授权，原有 `%sudo`、云镜像等广泛权限继续生效。所有显式 grants 都通过终端片段落实 PASSWD/NOPASSWD，并清除相应用户的 `exempt_group` 认证豁免；用只读 `sudo -ll` 检查实际 Defaults，输出不完整或存在会覆盖认证要求的命令/运行身份豁免时拒绝应用。凭据缓存、同身份执行及 PAM 仍遵循 sudo 的正常规则，PASSWD 不代表每次都重新弹出口令提示。

指定收紧账户后，Agent 还通过末尾专用拒绝规则覆盖此前直接和组授权，并仅放行这些账户的显式 grants；没有 grants 的指定账户不能 sudo。授权和收紧只支持标准本地 sudoers，主文件须以 `/etc/sudoers.d` includedir 结束，Agent 终端片段须最后解析。LDAP/SSSD、自定义策略插件或更晚的规则会明确拒绝应用。撤回收紧账户仅去掉相应拒绝规则，仍配置的 grants 继续生效；清空 grants 和收紧账户或关闭 sudo 才移除终端片段。原有管理员文件保持原样。

### 6.1 四项内核开关

四项默认关闭，保存在同一个 `policies.sysctl` 映射中；开关开启写入指定目标，关闭删除该键并在 enforce 撤回时恢复最初记录的运行值。已有非标准值加载时保留，页面显示实际配置值；其他自定义内核参数仍由高级输入管理。

| 开关对应参数 | 开启目标 | 作用及适用范围 |
|---|---|---|
| `kernel.dmesg_restrict` | `1` | 限制无相应能力的用户读取内核日志，降低敏感信息暴露 |
| `kernel.kptr_restrict` | `2` | 隐藏通过 `%pK` 输出的内核指针，包括特权用户读取；可能影响诊断 |
| `net.ipv4.conf.all.rp_filter` | `1` | 严格 IPv4 反向路径校验；实际取 all 与各接口值较大者，不自动修改接口/默认值；多网卡、非对称路由、VPN 应先验证连通性 |
| `net.ipv4.tcp_syncookies` | `1` | SYN 队列溢出时使用 cookies；不替代防火墙及容量规划 |

每项应用都读取原值、写入、回读验证，并保存重启配置。相同配置再次应用也检查运行值；enforce 在 `status_interval_seconds` 周期（默认 30 秒）核验并尝试修复所选策略。audit 仅检查和上报，不进入周期写入路径。缺失参数、权限不足、写入未生效均返回具体项错误，事务失败恢复文件与运行值。

### 6.2 策略状态与实际验收

“系统加固策略”是一次次策略核验，不是常驻服务，因此页面展示模式、检查时间、目标值、实际值及错误，不再以“运行 否”判断异常。`audit` 表示仅检查且已达标，`audit_drift` 表示仅检查未达标，`compliant` 表示 enforce 核验达标，`no_policies` 表示没有选择策略，`drift` 表示实际值偏离，`error` 表示检查或应用失败。`checked_at` 是核验时间，`applied_at` 是成功提交时间；单纯时间变化不产生异常历史。

SSH 核对活动 sshd 的 systemd MainPID、启动参数、实际监听端口、`sshd -t/-T` 和受支持 Match 条件的逐项有效值；来源限制还核对 nft 表归属、地址/端口、规则顺序及最终拒绝。允许来源是对 SSH 新连接的限制，保留已建立连接；其他防火墙仍可能拒绝允许来源，用户公钥可用性仍需从目标来源实测新连接。来源策略还依赖 `ss`（iproute2/iproute），由 `install_missing` 控制是否补装。

空闲超时通过新交互 Bash 加载实际 `/etc/profile`，检查 TMOUT 值及只读、导出属性；未加载片段或可被修改不算达标。只影响新登录的交互 Bash 提示符，不终止运行中的程序，也不覆盖其他 Shell。

GRUB 在改动前备份实际生成的 `grub.cfg` 和 `.new`，生成后检查语法、认证哈希、superusers 及菜单参数。开启单用户保护时必须存在经核验的恢复入口，所有恢复/救援或带单用户参数的入口都必须认证；普通启动可免认证，编辑入口和命令行仍受 superusers 保护。失败或进程中断恢复生成文件；旧版本没有生成文件快照的中断记录会重新生成并验证，不能恢复则保留错误与事务记录。

### 6.3 按机器发现账户并限制 SSH 登录

Agent 在安全扩展启用后读取本机 `/etc/passwd`，随组件状态上报账户名、UID、GID、Shell 及是否为交互 Shell；不采集口令字段、shadow、备注或主目录，不枚举 LDAP/SSSD 等目录账户。每个 `status_interval_seconds` 周期重新检查，账户增删或 Shell 变化会立即进入下一次状态上报；清单未变化时沿用默认五分钟快照。清单最多 256 项且不超过 16 KiB，超过上限明确标记为部分清单，优先展示交互 Shell 账户。

在“组件与主机策略”的 SSH 配置中选择目标机器，读取该机最新上报的账户，再选择允许登录的用户名。账户发现只说明该本地账户存在；Shell 标记不代表该账户已配置公钥或能够通过 PAM、账户锁定等认证检查。读取页面快照不触发远程扫描。尚未上报时先升级 Agent、启用安全扩展并等待状态上报；过期、错误和不支持的清单不能用于发现选择，手工白名单仍可保留。

从发现清单配置时，界面将配置下发绑定到该单台机器，避免不同机器的账户清单混用。切换或清除绑定后检查白名单并重新写入 YAML。新配置仍走原有完整 YAML 下发流程，保留原 history、监控及上报配置；Agent 应用时再次检查用户是否存在，配置校验和 SSH 重载成功后才确认。

要实际限制登录，开启 SSH 策略、将模式设为 `enforce`，并填写非空 `allow_users`。空名单表示不管理 `AllowUsers`，不表示拒绝所有用户。发现账户不会自动授权任何账户，也不会自动切换强制模式。仅关闭转发可使用已有的 `disable_forwarding: true` 开关；该开关与禁密码、用户白名单和强算法分别配置。

## 7. 任务执行结果与 cron

基础预设的 auditd 与原生 FIM 均覆盖以下标准 cron 范围：`/etc/crontab`、`/etc/cron.d`、`/etc/cron.hourly`、`/etc/cron.daily`、`/etc/cron.weekly`、`/etc/cron.monthly`、`/etc/cron.yearly`、`/etc/cron.allow`、`/etc/cron.deny`、`/etc/anacrontab` 和 `/var/spool/cron`。目录递归覆盖其内容，因此用户 crontab 及 `/var/spool/cron/crontabs` 也在范围内。它是明确的标准候选清单，不展开任意 `/etc/cron*` 通配符；额外自定义调度路径应显式添加。systemd timer 单元和运行时 transient timer 不自动纳入。

| 路径状态 | 处理方式 |
|---|---|
| 启用监控时已存在 | 建立静默基线，不把原有文件内容当新增告警 |
| 启用时不存在 | 不创建文件，不报缺失；保留候选路径并观察最近存在的父目录 |
| 后续出现 | 无需重启或重新下发，实时纳入并记录新增；新目录中的内容自动接入 |
| 内容、权限、属主变化或重命名替换 | 记录 warning 变更，同一次保存适当合并 |
| 删除、删除后重建 | 删除告警后继续等待，不重复报缺失；重建记录新增 |

原生 FIM 使用 inotify 触发及时采集，目录结构变化另触发合并补扫，周期扫描负责兜底。auditd 只为实际存在的标准 cron 路径加载 watch；后续出现、删除或重建按 `status_interval_seconds`（默认 30 秒）协调运行规则，不因初始缺少 cron.allow/deny 等可选文件阻止配置应用，也不扩大为整个 `/etc` 的审计。实时变更记录由 FIM 负责，auditd 补充有规则覆盖时的系统审计身份信息。

上述范围用于新基础预设和空路径默认值。已有显式非空的自定义路径不会被自动扩大；升级后应在页面重新载入基础预设或将所需路径合并到原配置，再下发。只更新二进制不会擅自替换已经下发的监控范围。

原生 FIM 已观察到的新增、修改、删除使用 warning 事件；在主控接收门槛不高于 warning 且 webhook 已启用时，变更会入库并进入通知队列。短暂创建后删除可记录已观察到的生命周期，但连续写入和编辑器原子保存会归并为规范化文件变更，不承诺每次原始写操作独立告警。停机、inotify 注册窗口或队列溢出仍需依靠错误记录及补扫核对；auditd 成功变更通常是 info，默认主控不会保留这些 info 记录。

监控 cron 文件只能证明任务配置发生变化。需要输出和退出码时，显式把该任务接入同一个二进制的包装入口：

```sh
/usr/local/anquan/anquan -task-run backup-job -- /usr/local/bin/backup --daily
```

例如原 crontab 命令为 `/usr/local/bin/backup --daily`，可在保留原调度时间和用户的前提下，用上面的包装命令替换命令部分。Agent 不会猜测、改写已有任务。

包装器直接执行 argv，不通过 Shell 拼接。需要 Shell 语法的既有任务可以指向管理员已有的绝对路径脚本。输出继续传向任务原 stdout/stderr，包装器同时捕获每路最多 8 KiB，使用 Base64 上传并标记是否截断；返回原任务退出码。开始、结束、耗时、失败和取消信息进入安全事件。

任务记录先写加密 spool；主控离线不阻止业务任务执行。spool 限制 1000 个文件/64 MiB，记录失败会在 stderr 说明，不把本来成功的业务命令改成失败退出。未包装任务、SIGKILL/断电打断的任务无法承诺有结束记录；开始记录可以保留为排查依据。

## 8. 新数据、接口和可靠性

新增 `security_event` 与 `component_status`，保持 envelope version=1。`component_status` 保存各组件启用、安装、运行状态、版本、配置 hash、实际应用时间、错误、策略检查结果，以及系统/内核/架构/BTF 信息、队列积压。

本地账户清单位于 `component_status.data.inventory.ssh_accounts`，含 `state`、`source`、`checked_at`、`total`、`truncated`、`users` 和可选 `error`；每个用户含 `name`、`uid`、`gid`、`shell`、`login_shell`。读取失败或遇到不符合现有 SSH 策略用户名规则的本地账户会报告错误和空清单，不将部分解析结果伪装成完整清单。旧 Agent 缺少该字段仍兼容；主控仅更新该机器的最新快照，账户清单变化本身不产生安全告警。

新增事件先加密持久化到磁盘，再发送给配置中的主控；每个主控数据库事务提交后 ACK，Agent 保存每个目标的确认进度。进程重启继续补传，Master 按原事件 ID 幂等。一个主控离线不会阻止尝试把后续事件发送给健康主控；其未确认副本仍占队列。事件创建时的目标集合会保留，不会因后续切换 server 而静默放弃旧目标。

队列满时追加日志来源不推进已保存的游标。inotify 本身是有限内核队列，不能承诺断网、溢出时仍保留全部短暂活动；会结合错误状态和周期核对发现缺口。超长日志会形成明确的 oversize 事件，原始内容留在主机源日志，避免一条大记录永久阻塞采集。状态中的策略检查长文本会截断；仍超出传输大小时省略检查明细，并附 `omitted_checks` / `details_truncated` 标记，保留组件基本健康信息。

| 接口 | 用途 |
|---|---|
| `GET /api/settings/security-profile/defaults` | 获取默认组件预设 |
| `POST /api/settings/security-profile/compose` | 解析/安全合并 security 和原 YAML |
| `GET/PUT /api/settings/package-downloads` | 查看下载状态，限时开启/关闭安装下载并管理允许软件源域名 |
| 原 `/api/settings/agent-config-deliveries` | 原配置下发及状态，不另建控制通道 |
| `GET /api/security/status?machine_ip=...` | 各机器最新组件快照 |
| 原 `/api/events?type=security_event` | 安全事件查询 |
| `GET /api/security/sudo-sessions` | 录制会话、各文件收齐状态 |
| `GET /api/security/sudo-sessions/{id}/files/{file}` | 已认证下载完整录制文件；未收齐返回 409 |

普通进程、命令、组件状态只入库；`security_event` 的 warning/error/critical 才进入原 webhook 队列。sudo 二进制块保存到专表，不重复塞入普通事件表或发送通知。

本版只提供稳定文件事后上传、下载供 `sudoreplay`，没有网页实时会话播放器。下载一个会话的 log/log.json、timing 和 I/O 文件到同一目录后，使用 sudo 自带工具回放。正在变化的录制会按新一代会话数据重新上传，不宣称是连续的实时视频流。

## 9. 验收与已知边界

先在测试 Linux 主机使用基础预设，验收以下结果：配置已应用；auditd/sudo 状态可用；关键文件内容与 chmod/chown 变化入库；Agent 重启后的变化仍能与已有 native FIM 基线比较；Master 短暂停机后可以补传；失败 SSH 达阈值告警；包装任务保留退出码；启用 sudo 上传后可以下载收齐文件。

本地开发验证包含 Windows Go 单元/集成测试、Linux amd64/arm64 编译、Master 迁移/UDP ACK/下载测试、Vue 类型检查/生产构建，以及隔离本机配置下发联调。Windows 不执行 auditd、Tetragon、nft、GRUB 的真实安装与内核功能；Linux 权限、发行版、内核和实际 reload 仍需目标主机验收，不能把 mock 测试等同于生产安装验证。

- Tetragon 自动安装需要 amd64/arm64、systemd、内核 BTF；有 Master 时还需要开启下载窗口，且 Master 能访问可信发布源和重定向目标。校验或安装失败会明确显示，不能以日志文件存在替代功能验收。
- SSH 策略要求主配置已有标准 drop-in Include；不自动覆盖管理员主配置。socket activation、自定义 sshd `-f/-p/-o` 以及无法穷举的 Match 条件会明确报错；不把无法验证的部署标为达标。
- GRUB 自动应用仅支持提供 `update-grub`、`grub-script-check` 且使用标准 `/boot/grub/grub.cfg` 的部署；动态外部配置等无法核验的情况会拒绝应用。认证不等于磁盘加密，也不阻止物理外部介质启动。Ctrl+Alt+Del 要求 systemd 可回读 burst action，自定义同名 target/alias 不会被强制覆盖。
- 原有 `FilesMonitoring`/进程巡检兼容保留；native FIM 的持续基线是独立的新机制。同一路径同时配置旧、新监控可能产生两类记录，应按目标范围选择。
- 全量安全事件、sudo 文件和源日志还没有自动保留期限清理，需要按主机数量、事件量和存储容量规划。
- 原配置 TCP/UDP 的内网信任模型保持不变。age 隐藏配置明文不等于控制端身份认证；主控端口应继续放在受信任网络和既有访问控制内。
